## 案例 1：技術講座範例（AI Coding 工作坊）

### 原始逐字稿概況
- **主題**：AI Coding 實戰工作坊
- **時長**：2 小時
- **講者**：資深工程師
- **受眾**：初學者到中階開發者

### Study Guide 產出

#### Executive Summary

**3 個關鍵 Takeaways：**
1. AI Coding 不是取代開發者，而是加速「概念到程式碼」的轉換
2. Prompt Engineering 的核心是「給出脈絡」而非「寫精準指令」
3. 最高 ROI 的應用場景：測試撰寫、API 串接、重構舊程式碼

**誰適合讀這份文件：**
想提升開發效率的工程師、對 AI Coding 好奇但不知從何下手的開發者

**預期收穫：**
讀完後你能立刻用 AI 工具寫出第一個測試案例，並知道如何逐步整合到工作流程中

---

#### Key Concepts

**概念 1：AI Coding 的本質是「協作」而非「外包」**

- **定義**：AI 是 pair programmer，不是自動化工具
- **為什麼重要**：誤以為 AI 能全自動寫程式 → 產出低品質程式碼 → 失去信任
- **實際應用**：你負責架構與決策，AI 負責實作與優化

**概念 2：Prompt 的黃金公式：Context > Instruction**

- **定義**：給 AI 足夠的脈絡比給精確指令更重要
- **為什麼重要**：脈絡不足 → AI 猜測 → 產出不符預期
- **實際應用**：「這是一個 Express.js 專案，使用 TypeScript，遵循 Clean Architecture」vs「寫一個 API」

**概念 3：三大高 ROI 場景**

- **測試撰寫**：重複性高、規則明確
- **API 串接**：文件完整、模式固定
- **重構舊程式碼**：邏輯保留、結構改善

---

#### Examples & Cases

**範例 1：用 AI 寫單元測試**

**情境**：有一個 `calculateDiscount` 函式，需要測試
```typescript
function calculateDiscount(price: number, userTier: string): number {
  // ...
}
```

**做法**：
```
我有一個折扣計算函式，使用者分三層（silver/gold/platinum），
折扣分別是 5%/10%/15%。請幫我寫完整的單元測試，
涵蓋正常情境、邊界情況、錯誤處理。使用 Jest。
```

**結果**：AI 產出 12 個測試案例，涵蓋所有情境

**範例 2：重構 legacy code**

**情境**：一個 200 行的 God Function 需要拆分

**做法**：
```
這個函式做了太多事：驗證輸入、呼叫 API、處理錯誤、格式化輸出。
請幫我拆成多個 single responsibility 的函式，保持原本邏輯不變。
```

**結果**：AI 拆成 5 個函式，每個職責清晰，附上重構前後對照

#### Actionable Steps

**立即可做（今天）：**
- [ ] 選一個你最常寫的測試類型（API 測試、單元測試），用 AI 寫一次
- [ ] 記錄：AI 產出的程式碼哪些可以直接用，哪些需要修改

**一週內：**
- [ ] 選一個真實專案的小功能（如：新增一個 API endpoint），從頭到尾用 AI 協作完成
- [ ] 觀察：哪些環節 AI 幫助最大，哪些環節仍需要你主導

**長期（持續優化）：**
- [ ] 建立你的「Prompt 模板庫」：把有效的 Prompt 記錄下來，重複使用
- [ ] 每週回顧：AI Coding 讓你節省多少時間，用在哪些任務上

## 案例 2：商業講座範例（個人品牌經營）

### 原始逐字稿概況
- **主題**：個人品牌從 0 到 1
- **時長**：90 分鐘
- **講者**：自媒體創業者
- **受眾**：想建立個人品牌的上班族

### Study Guide 產出

#### Executive Summary

**3 個關鍵 Takeaways：**
1. 個人品牌 = 你的專業 × 你的聲音（不是完美形象）
2. 最快起步方式：選一個平台，持續 30 天，每天發一則內容
3. 流量不是目標，信任才是——100 個信任你的人比 10000 個陌生粉絲有價值

**誰適合讀這份文件：**
想建立個人品牌但不知從何開始的人、已經開始但感覺沒方向的創作者

**預期收穫：**
讀完後你能選定第一個平台，寫出第一則貼文，知道如何持續 30 天

---

#### Key Concepts

**概念 1：個人品牌公式**

- **定義**：個人品牌 = 專業價值 × 個人聲音
- **為什麼重要**：很多人只做一半（純專業內容很無聊，純個人生活很空洞）
- **實際應用**：分享專業知識時，加入你的觀點、經驗、甚至失敗

**概念 2：30 天挑戰法則**

- **定義**：選一個平台，每天發一則內容，持續 30 天
- **為什麼重要**：克服完美主義、找到自己的聲音、建立習慣
- **實際應用**：不求完美，只求發布——重點是「做」而非「想」

**概念 3：信任 > 流量**

- **定義**：100 個信任你的人比 10000 個陌生粉絲有價值
- **為什麼重要**：流量不等於商業價值，信任才能轉換
- **實際應用**：回覆每一則留言、分享真實經驗、承認不足

---

#### Examples & Cases

**範例 1：工程師的個人品牌起步**

**情境**：後端工程師，想分享技術但怕太無聊

**做法**：
- 選平台：Threads（因為 IT 社群活躍）
- 內容公式：「今天解了一個 bug」+「我學到什麼」+「你可能也會遇到」
- 持續 30 天，不求完美

**結果**：第 15 天開始有人主動私訊請教問題，第 30 天累積 200+ 真實互動

**範例 2：設計師的信任建立**

**情境**：UI/UX 設計師，粉絲數 500，但沒有接案機會

**做法**：
- 改變策略：從「展示作品」改為「分享設計思考過程」
- 公開失敗案例：「這個設計我做錯了什麼」
- 回覆每一則留言，認真交流

**結果**：粉絲數沒增加，但 3 個月內接到 5 個案子（都來自互動過的人）

---

#### Actionable Steps

**立即可做（今天）：**
- [ ] 選一個平台（Threads/LinkedIn/Instagram）
- [ ] 寫下你的「專業價值」是什麼（一句話）
- [ ] 發第一則貼文：分享你今天學到的一件事

**一週內：**
- [ ] 持續發 7 天，觀察哪種內容有互動
- [ ] 回覆每一則留言，開始建立關係

**長期（持續優化）：**
- [ ] 完成 30 天挑戰
- [ ] 每週回顧：哪些內容有共鳴，哪些沒有
- [ ] 建立「內容靈感庫」：把日常觀察記錄下來

---

#### Review Questions

**理解層次：**
1. 個人品牌公式是什麼？為什麼兩者缺一不可？
2. 為什麼說「信任比流量重要」？

**應用層次：**
3. 如果你要開始 30 天挑戰，你會選哪個平台？為什麼？
4. 你的「專業價值 × 個人聲音」是什麼？試著用一句話描述

**創造層次：**
5. 設計你的第一週內容計畫：7 天要發什麼主題？
