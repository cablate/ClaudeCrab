# Session Handoff

把當前對話的所有關鍵 context 壓縮成一段 prompt，讓使用者貼到新 session 後，新 AI 能直接接手工作，體感等同在同一個 session 中對話。

## 為什麼需要這個

長 session 累積的 cache token 會拖慢回應、吃掉額度。但直接開新 session 會丟失所有對話 context。
這個 skill 解決的問題是：**壓縮 context，不丟失 context。**

## 執行步驟

1. 回顧整段對話歷史，提取所有關鍵資訊
2. 按照下方結構組織內容
3. 輸出一個完整的 code block（用 ```markdown 包裹），使用者直接複製貼上即可

## 提取清單

**每一項都必須逐項掃過，有就寫，沒有才跳過。不准省略、不准摘要帶過。**

### 任務與進度
- **任務目標**：我們在做什麼、為什麼做
- **當前狀態**：做到哪了、什麼完成了、什麼還沒做
- **下一步**：新 session 應該接著做什麼（寫成可直接執行的指令）

### 使用者在本次對話中給過的指示
這是最容易在換 session 時丟失的資訊。逐條列出，保留原話：
- **回應方式的要求**：語氣、格式、風格、「永遠要 X」「不要 Y」
- **對 AI 行為的修正**：使用者糾正過的方向、打斷重來的原因
- **明確的偏好與決策**：選了什麼方案、為什麼、排除了什麼

### 工作 Context
- **工作目錄與相關檔案**：路徑 + 每個檔案的狀態（已改/新建/待改）+ 改了什麼
- **關鍵決策與理由**：做了什麼選擇、為什麼這樣選（保留理由，避免新 session 重新討論）
- **踩過的坑**：失敗過的方案、環境限制、要避開的路線
- **技術細節**：架構、依賴、版本、特殊配置（只記新 session 需要知道的）

### 未收尾的事項
- **未解決的問題**：還沒答案的疑問、待確認的事項
- **外部資源**：參考過的文件、URL、API

## 輸出原則

- **原話保留（verbatim）**：使用者的指示、修正、偏好，用引號逐字保留，不改寫不摘要。這是這份 handoff 最重要的價值——新 session 要能「聽到」使用者本人的聲音，而不是 AI 的轉述
- **不省略不合併**：每條指示、每個修正都獨立列出。寧可多一行，不可吞掉一條
- **具體不抽象**：寫檔案路徑、函式名、指令、錯誤訊息，不寫「某個檔案」「那個 bug」
- **可執行**：「下一步」要寫到新 session 的 AI 拿到就能直接動手的程度
- **不複製檔案內容**：只記路徑和關鍵發現，不把整個檔案貼進來
- **不重複 memory**：如果某些資訊已經存在 memory 系統中，不需要重複寫進 handoff

## 輸出格式

輸出一個 markdown code block，結構如下。每個 section 只在有內容時才出現：

```
# Session Handoff — {YYYY-MM-DD}

## 背景
{一到兩句話描述任務和動機}

## 工作目錄
{專案路徑}

## 進度
### 已完成
- {具體完成事項，附檔案路徑}

### 進行中 / 待完成
- {未完成事項，附當前狀態和卡在哪}

## 關鍵決策
- {決策} — 因為：{原因}

## 相關檔案
| 檔案 | 狀態 | 說明 |
|------|------|------|
| {path} | 已改/新建/待改 | {做了什麼或要做什麼} |

## 踩過的坑
- {失敗的方案或要避開的路線}

## 使用者在本次對話中給過的指示
（逐條列出，保留原話，不合併不省略）
- 回應方式："{原話}"
- 行為修正："{原話}" — 背景：{為什麼這樣糾正}
- 偏好/決策："{原話}"

## 未解決
- {待確認或還沒答案的問題}

## 下一步
{寫成直接可執行的指令，新 session AI 拿到就能動手}
```

## 補充行為

- 產出 handoff 後，明確告知使用者：「以上是完整交接內容，還是有遺漏？」——確認完整性
- 如果對話中有產出過 plan 或 task list，整合進「進度」和「下一步」
- 如果對話中有多個獨立任務，分別列出，不要混在一起
- 如果使用者在對話中給過的指示超過 3 條，在 handoff 末尾加一行確認：「以上共 N 條使用者指示，已全部列出。」
