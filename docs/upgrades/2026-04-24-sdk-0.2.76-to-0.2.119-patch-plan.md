## 三個新 patches

### Patch A — thinking + extraArgs cluster（合併舊 #3 + #4）

**Find**（uniqueness 已驗 = 1）:
```
extraArgs:{},thinkingConfig:void 0,maxTurns:void 0,maxBudgetUsd:void 0,
```

**Replace**:
```
extraArgs:$.extraArgs??{},thinkingConfig:$.thinking??void 0,maxTurns:$.maxTurns??void 0,maxBudgetUsd:$.maxBudgetUsd??void 0,
```

**為什麼合併**：4 個欄位在 sdk.mjs 裡連續出現，單一 `find` 比分 4 個 patch 簡單且 uniqueness 檢查一次。

### Patch B — F9 constructor（重寫舊 #5）

**Find**（uniqueness 已驗 = 1）:
```
new F9(Q,!1,$.canUseTool,$.hooks,this.abortController,new Map,void 0,{planModeInstructions:$.planModeInstructions})
```

**Replace**:
```
new F9(Q,!1,$.canUseTool,$.hooks,this.abortController,(()=>{let m=new Map;if($.mcpServers)for(let[k,v]of Object.entries($.mcpServers))if(v.type==="sdk"&&"instance"in v)m.set(k,v.instance);return m})(),void 0,{planModeInstructions:$.planModeInstructions,systemPrompt:$.systemPrompt})
```

**變動點**：
- `new Map` → IIFE 建立 Map 並從 `$.mcpServers` 填入（同舊 patch #5 邏輯）
- `{planModeInstructions:$.planModeInstructions}` → 追加 `systemPrompt:$.systemPrompt`（保留 planModeInstructions 不破壞 plan mode 新功能）

**注意**：舊 patch 的變數名是 `Q` 不是 `$`（0.2.76 的 cQ 用 `Q` 作建構子參數，0.2.119 改用 `$`）。所有 replace 文字都要用 `$`。

## 驗證流程

**1. 升級前備份**:
```bash
# 備份當前 0.2.76 的 lockfile + 已 patched 的 sdk.mjs 已經在 git 裡 (_special-research/sdk.mjs.v76-patched)
git log --oneline -3  # 確認最新 commit 包含備份
```

**2. 升級 SDK**:
```bash
npm install @anthropic-ai/claude-agent-sdk@0.2.119
# postinstall 自動執行 patch-sdk-v2.cjs
```

**3. Postinstall 輸出應為**:
```
[patch-sdk-v2] Patched sdk.mjs (xxxxxxxx → yyyyyyyy)
[patch-sdk-v2] Backup: sdk.mjs.pre-patch
  ✓ thinking-and-extraArgs: Allow V2 sessions to configure ...
  ✓ F9-initConfig-and-mcpServers: Build sdkMcpMap from ...
```

若看到 `ERROR: Patch "xxx" target not found` → SDK 又改了，需重新 inspect `sdk.mjs.pre-patch`。

**4. 功能驗證**（升完啟動 bot 後從 log 撈）:
- `sdk.cli_override` 事件存在且 `cliVersion` 是 2.1.119（CLI 不用動）
- `V2 persistent session created` + V1 fallback 0 次
- 送一則需要 thinking 的訊息，確認 thinking block 有出現（確認 patch A 有效）
- 啟用 SDK MCP server 測試，確認 MCP tool 可被呼叫（確認 patch B mcpServers 部分有效）
- 設定 systemPrompt 的 agent 送訊息，確認系統提示有被 honored（確認 patch B systemPrompt 部分有效）

## Rollback 流程

**情境 1：postinstall patch 失敗**
- patch-sdk-v2.cjs 會直接 `process.exit(1)`，不會產生破壞性變動
- `npm install @anthropic-ai/claude-agent-sdk@0.2.76` 回到已知 good state

**情境 2：patch 成功但 runtime 爆掉**
```bash
# 回滾 package.json 跟 patch script
git checkout HEAD~1 -- package.json package-lock.json scripts/patch-sdk-v2.cjs
npm install
# 自動跑舊版 patch script → 重新 patch 回 0.2.76
```

**情境 3：需要比對舊版邏輯**
- `_special-research/sdk.mjs.v76-patched`（已 commit，396KB）是 0.2.76 patched 版本的快照
- `node_modules/@anthropic-ai/claude-agent-sdk/sdk.mjs.pre-patch` 是當下 SDK 的原版（由 patch script 自動建立）

## 風險評估

| 風險 | 機率 | 影響 | 緩解 |
|------|------|------|------|
| Anchor uniqueness 變化（未來升到 0.2.120+） | 中 | patch 失敗 → 啟動時 npm install 就炸 | script 已有 uniqueness check，失敗時 exit 1 |
| F9 簽章再改（多 slot 或換位） | 中 | Patch B find 失敗 | 手動重新 inspect cQ 建構子 |
| planModeInstructions 改名 | 低 | Patch B find 失敗 | 同上 |
| SDK 把 mcpServers 也接上 cQ | 低 | 不傷，patch 會 skip（或 find not found） | 把 Patch B 拆成只處理 systemPrompt 即可 |

**關鍵**：anchor-based matching 的魯棒性全靠 `'Cannot send to closed session'` 這個錯誤訊息字串保持不變。如果上游改這個錯誤訊息，所有 patch 都要重找 anchor。
