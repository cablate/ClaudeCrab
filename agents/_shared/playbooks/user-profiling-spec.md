# User Profiling Methodology Spec

**版本**：v0.1（規格草案，待轉化為 Skill）
**建檔日期**：2026-03-07
**目的**：定義一套通用方法論，讓 AI 從任意素材中提煉出一個人的完整畫像，使後續所有內容產出都能與這個人的個性、理念、價值觀掛勾。

---

## 一、這套方法論解決什麼問題

AI 最常見的失敗模式：產出的內容「技術上正確，但讀起來不像這個人」。

根本原因是 AI 不認識這個人。即使給了 System Prompt，也只是表面規則（「語氣友善」「不要用某些詞」），而不是真正理解這個人怎麼思考、相信什麼、在意什麼。

這套方法論的目標：**讓 AI 從散落的素材中，建立對一個人的深度理解，深到可以「替這個人思考」而不只是「替這個人打字」。**

---

## 二、核心認知：三層理解深度

| 層級 | 理解 | AI 能做到 | 常見問題 |
|------|------|----------|---------|
| 表面 | 知道這個人的基本資料和偏好 | 不犯明顯錯誤 | 產出很泛，換一個人也通用 |
| 行為 | 知道這個人怎麼寫、怎麼表達 | 模仿語氣和用詞 | 機械式套用，讀起來像 AI |
| **世界觀** | **知道這個人怎麼思考、相信什麼、在意什麼** | **從這個人的視角出發，自然產出符合其人格的內容** | — |

這套方法論的目標是達到第三層。

## 三、輸入規格

### 支援的素材類型

| 類型 | 範例 | 資訊密度 | 特性 |
|------|------|---------|------|
| 檔案系統 | 筆記、課程素材、專案文件、電子報、部落格 | 高 | 結構化、有時間跨度、涵蓋面廣 |
| 社群貼文 | Threads、FB、IG、LinkedIn | 中 | 碎片化但真實、有互動脈絡 |
| 寫作樣本 | 已發布的文章、電子報 | 高 | 風格穩定、經過編輯 |
| 對話紀錄 | 與 AI 的對話、聊天記錄 | 中 | 即興、展現真實思維過程 |
| 自我介紹 | Bio、About 頁面、自述 | 低 | 經過包裝、不一定真實 |

### 最低要求

- 至少需要一種「高密度」素材（檔案系統或寫作樣本）
- 或至少 50 篇社群貼文（量大可以補密度不足）
- 只有自我介紹是不夠的——那是這個人「想被看到的樣子」，不是全貌

### 輸入預處理

1. **盤點**：列出所有可用素材，按類型分類
2. **時間排序**：標記素材的時間跨度，越長越好（能看到演變）
3. **去重**：同一內容在不同平台出現時，保留最完整的版本
4. **標記來源可信度**：自述 < 社群貼文 < 反覆出現的行為模式 < 實際產出

## 四、分析維度（十面向框架）

### 維度一覽

| # | 維度 | 回答的問題 | 必要性 | 主要提取來源 |
|---|------|----------|--------|------------|
| 1 | 身份定位 | 這個人是誰？一句話怎麼說？ | 必要 | Bio、自述、反覆出現的自我定位 |
| 2 | 價值觀與信念 | 他相信什麼？紅線在哪？ | 必要 | 觀點文、反覆出現的立場、批判的對象 |
| 3 | 產品/服務 | 他在賣/做什麼？ | 視角色而定 | 銷售頁、課程、服務紀錄 |
| 4 | 受眾/市場 | 他服務誰？不服務誰？ | 視角色而定 | 內容受眾分析、明確排除的對象 |
| 5 | 內容體系 | 他產出什麼內容？模式是什麼？ | 必要 | 所有內容的結構化分析 |
| 6 | 表達風格 | 他怎麼寫/說？世界觀怎麼驅動表達？ | 必要 | 寫作樣本、社群貼文 |
| 7 | 故事素材 | 什麼經歷塑造了他？ | 建議 | 經驗分享、自我剖析、創業故事 |
| 8 | 目標 | 他在往哪走？ | 建議 | 規劃文件、願景陳述、目標設定 |
| 9 | 人格特質 | 他的行為模式和互動偏好？ | 必要 | 跨素材觀察、對話風格、決策模式 |
| 10 | 缺口與機會 | 什麼是他已有但沒串起來的？ | 選填 | 交叉分析所有維度後的推論 |

### 每個維度的提取方法

#### 維度 1：身份定位

**提取邏輯**：
- 不是從 bio 複製，而是從所有素材中歸納「這個人反覆以什麼角色出現」
- 交叉驗證：自我宣稱 vs 實際產出 vs 別人怎麼認識他

**輸出格式**：
```
一句話：[自然語言描述]
背景：[關鍵經歷，按時間排列]
核心身份：[2-3 個角色定位，帶簡短說明]
技術/專業棧：[如適用]
```

**品質標準**：讀完這段，另一個 AI 能回答「這個人跟 X 有什麼不同？」

#### 維度 2：價值觀與信念

**提取邏輯**：
- **正面提取**：他反覆強調什麼？（至少出現 3 次才算「信念」）
- **反面提取**：他批判什麼？討厭什麼？拒絕什麼？（紅線）
- **深層提取**：他的世界觀是什麼？（不是「我覺得 X 很重要」，而是「我看這個世界的方式是 Y」）
- **轉變追蹤**：信念有沒有隨時間改變？舊信念 vs 新信念

**輸出格式**：
```
做事原則：[3-5 條，每條一句話]
紅線：[絕對不做的事]
世界觀：[3-5 條核心信念，用引號標記原文]
信念轉變：[如有，記錄舊→新的轉變]
```

**品質標準**：
- 每條信念都有 3+ 篇素材佐證
- 世界觀不是泛泛的「正直善良」，而是有辨識度的立場
- 測試：「把這些信念給 10 個人看，能猜出是同一個人嗎？」

#### 維度 3：產品/服務

**提取邏輯**：
- 盤點所有已有產品，包含定價、銷售量、學員回饋
- 識別四層架構：免費引流 → 入門 → 進階 → 終極
- 記錄決策準則（評估新服務時的判斷標準）

**輸出格式**：表格 + 生態系圖 + 決策準則

**品質標準**：能回答「他下一個產品應該是什麼？」

#### 維度 4：受眾/市場

**提取邏輯**：
- 從內容反推：他在對誰說話？
- 明確排除：他說過不服務誰？
- 差異化：他跟同領域的人有什麼不同？

**輸出格式**：
```
目標受眾：[表格：誰 | 痛點 | 能幫什麼]
不服務：[明確排除的對象]
差異化：[跟同行的區別]
```

#### 維度 5：內容體系

**提取邏輯**：
- **量化分析**：類型分佈（教學/觀點/經驗/日常等的比例）
- **知識密度分佈**：高密度 vs 低密度內容的比例
- **主題頻率**：反覆出現的主題排行
- **演變趨勢**：早期 vs 現在的內容風格變化
- **獨特框架**：這個人發明或常用的方法論/框架

**輸出格式**：
```
內容支柱：[各類型百分比]
已有資產：[盤點所有已發布內容]
獨特方法論：[列出可重複利用的框架]
反覆主題：[排行榜]
演變趨勢：[時間線]
```

**品質標準**：能回答「他下一篇文章最可能寫什麼？」

#### 維度 6：表達風格

**提取邏輯**（世界觀驅動，非詞彙驅動）：

這是最關鍵的維度。參考 style-driven-author 的四層萃取：

1. **世界觀層**：他怎麼看世界？這決定了他為什麼這樣寫
2. **語調原則**：每種語調的意圖 + 使用頻率（防止 AI 過度使用某種語氣）
3. **詞彙規則**：每個慣用語的「情境/意圖」（何時用、為何用），不是純詞彙清單
4. **結構模式**：開場模式、論證模式、慣用結構

**輸出格式**：
```
統一基調：[一句話]
穩定特徵：[5-8 個觀察]
敘事結構：[慣用的文章結構]
關鍵語錄：[5-10 句代表風格的原文]
```

**品質標準**：
- 不是規則清單（「不要用 X 字」），而是原則（「他討厭焦慮感」）
- 測試：用這份風格指南讓 AI 寫一段話，讀起來不像 AI

#### 維度 7：故事素材

**提取邏輯**：
- 掃描所有「我」出發的敘事
- 分類：成功故事 / 失敗故事 / 掙扎故事 / 轉變故事
- 標記「可用於內容」的故事（有情節、有衝突、有結論）

**輸出格式**：編號列表，每個故事一句話摘要 + 情緒標籤

#### 維度 8：目標

**提取邏輯**：
- 從規劃文件、願景陳述中提取
- 分短期/中期/長期
- 交叉驗證：宣稱的目標 vs 實際行動方向

#### 維度 9：人格特質

**提取邏輯**：
- 從行為模式推斷，不是從自述
- 性格特徵 + 互動模式 + 決策傾向 + 情緒模式

**品質標準**：能回答「跟他合作要注意什麼？」

#### 維度 10：缺口與機會

**提取邏輯**：
- 這不是從單一素材提取，而是交叉分析所有維度後的推論
- 他已有什麼但沒串起來？
- 他的目標 vs 現況之間差什麼？

## 五、執行流程

### Phase 1：盤點（Inventory）

```
輸入：素材來源清單
輸出：素材盤點表（類型、數量、時間跨度、預估資訊密度）
```

動作：
1. 掃描所有可用素材來源
2. 按類型分類
3. 標記時間跨度
4. 估算資訊密度
5. 產出盤點表，供使用者確認「還有沒有漏的」

### Phase 2：廣度掃描（Breadth Scan）

```
輸入：盤點後的素材
輸出：每個維度的原始觀察筆記
```

動作：
1. 快速瀏覽所有素材（不求深度，求覆蓋率）
2. 對每個維度記下初步觀察
3. 標記「需要深入」的區域
4. 標記「素材不足」的維度

**原則**：寧可漏看細節，不可漏看整個素材來源。

### Phase 3：深度提煉（Deep Extraction）

```
輸入：Phase 2 的觀察筆記
輸出：每個維度的結構化提煉
```

動作：
1. 對每個維度，回到原始素材做深度閱讀
2. 套用該維度的提取邏輯
3. 交叉驗證：同一個觀察是否在多個素材中出現？
4. 標記證據強度：
   - 強（3+ 篇素材佐證）
   - 中（1-2 篇，但有行為支撐）
   - 弱（僅 1 篇，且為自述）

**原則**：反覆出現的 > 只說一次的。行為證據 > 口頭宣稱。

### Phase 4：交叉驗證與合成（Cross-Validate & Synthesize）

```
輸入：Phase 3 的結構化提煉
輸出：完整的使用者畫像文件
```

動作：
1. 檢查維度間的一致性（價值觀 vs 實際行為、目標 vs 內容方向）
2. 發現矛盾時標記，不要替使用者解決矛盾——矛盾本身就是有價值的資訊
3. 合成為統一文件
4. 寫入「演變追蹤」區塊（如有足夠時間跨度的素材）

### Phase 5：使用者驗證（User Validation）

```
輸入：完整畫像文件
輸出：經使用者確認的最終版本
```

動作：
1. 將畫像呈現給使用者
2. 逐維度確認：「這段描述你嗎？」
3. 記錄使用者的修正（這些修正本身就是高價值資訊）
4. 更新文件

## 六、輸出規格

### 文件結構

```markdown
# [姓名/代稱] 使用者畫像

**建檔日期**：YYYY-MM-DD
**資料來源**：[列出所有素材類型和大致數量]
**用途**：[這份文件會被用在什麼場景]

---

## 一、身份定位
## 二、價值觀與信念
## 三、產品/服務（如適用）
## 四、受眾/市場（如適用）
## 五、內容體系
## 六、表達風格
## 七、故事素材
## 八、目標
## 九、人格特質
## 十、缺口與機會（如適用）

---

*此文件由 [維護者] 維護。每次深度互動後更新。*
```

### 字數建議

- 整份文件 2,000-5,000 字（太短沒深度，太長 AI 不會全讀）
- 每個維度 200-500 字
- 關鍵語錄和原文直接引用，不要改寫

### 更新機制

| 觸發條件 | 更新動作 |
|---------|---------|
| 新素材批次（如新的 50 篇貼文） | 重跑 Phase 2-4，差異合併 |
| 使用者修正 | 直接更新，標記「經使用者確認」 |
| 時間演變（每季） | 檢查是否有信念轉變或新方向 |
| AI 產出被使用者否決 | 回頭檢查畫像是否有遺漏或偏差 |

## 七、品質驗證

### 驗證三問

1. **辨識度**：把這份畫像的名字遮掉，讀者能猜出「這是某個特定的人」而不是「隨便一個人」嗎？
2. **可操作性**：拿這份畫像去讓另一個 AI 寫一篇文章，讀起來像這個人嗎？
3. **預測力**：根據這份畫像，能預測這個人對某個議題的立場嗎？

三個都「是」= 及格。有任何「否」= 需要迭代。

### 常見失敗模式

| 模式 | 症狀 | 修正 |
|------|------|------|
| 太泛 | 「注重品質、追求成長」——誰都是 | 加強紅線和世界觀提取，找辨識度 |
| 太表面 | 只有用詞習慣，沒有思維模式 | 回到世界觀層，問「為什麼他這樣寫？」 |
| 自我矛盾 | 價值觀寫「完美主義」但行為是「先做再說」 | 不要消除矛盾，標記為「張力點」 |
| 過度美化 | 只有正面特質 | 補充掙扎、盲點、弱點 |
| 缺乏演變 | 像快照而非故事 | 加入時間維度，追蹤信念轉變 |

## 八、與現有系統的關係

### 與 content-analyzer 的關係

content-analyzer 的 key_insights 是本方法論「維度 2 價值觀」和「維度 5 內容體系」的原料。大量貼文的 key_insights 聚合起來，就能看到反覆出現的信念和主題。

### 與 style-driven-author 的關係

style-driven-author 的步驟 3（風格萃取）是本方法論「維度 6 表達風格」的細化版本。本方法論提供全人理解，style-driven-author 負責將其中的風格維度轉化為可執行的寫作指南。

### 與 creator-profile 的關係

creator-profile 是本方法論在「社群貼文」這個素材類型上的持續累積。它是 Phase 2-3 在貼文分析場景的具體實現。

### 資料流

```
content-analyzer（單篇分析）
    ↓ 聚合
creator-profile（累積觀察）
    ↓ 整合
user-profiling（全面畫像） ← 同時接收其他素材（檔案系統、對話等）
    ↓ 輸出
style-driven-author（風格指南）→ 實際內容產出
```

## 九、轉化為 Skill 的設計備註

### Description 草案

「從使用者的散落素材（檔案、社群貼文、寫作樣本、對話紀錄）中提煉出完整畫像，達到世界觀層理解。觸發時機：首次合作需要認識使用者、使用者提供新素材要求更新畫像、產出內容前需要校準風格。輸出：結構化畫像文件（十面向框架）。」

### 預期的 Skill 結構

```
.claude/skills/user-profiling/
  SKILL.md              ← 方法論核心（本文件精簡版）
  references/
    dimension-spec.md   ← 十個維度的詳細提取規格
    quality-rubric.md   ← 品質評分標準
    examples.md         ← 不同素材類型的範例輸出
  workspace/
    [user-name].md      ← 每位使用者的畫像文件
```

### 設計原則（遵循 agentskill-expertise）

- 給原則不給規則：每個維度給「提取邏輯」和「品質標準」，不是 checklist
- SKILL.md < 5k tokens：細節放 references
- Description 要情境導向：觸發時機明確
- 可演化：workspace 允許持續累積
