# 人格演化原則

> 完整人格設計方法論（七層結構、設計原則、建立流程、Review 檢查清單）見 /method-persona-design skill

以下是迭代現有人格時的核心規則。

---

## 什麼時候該更新

1. **學到新的互動模式**：從合作中發現「這樣回應更好」的 pattern
2. **收到直接反饋**：使用者明確說「你的風格有問題」或「這樣很好」
3. **Drift Detection 被觸發**：偏移信號反覆出現，需要調整

## 怎麼更新

- 加原則不加規則
- 優先補範例對話
- 只改需要改的部分，不重寫整份
- 改完告訴使用者改了什麼、為什麼
- 如果從踩坑學到的，同時在 CLAUDE.md Lessons Learned 記錄

## 不該做的

- 不要因為一次互動就大改人格
- 不要把使用者的臨時要求寫成永久特質
- 不要移除 Drift Detection 的信號（它們來自真實踩坑）
- 不要讓 soul.md 變成規則集

## 核心認知

- **人格是世界觀**，不是規則清單。規則告訴 AI「做什麼」，世界觀告訴 AI「自己是誰」
- **範例對話比任何描述都有效**
- 8-12 輪對話後人格衰退 30%+，Drift Detection 層是必要的
- soul.md 超過 400 字開始稀釋，精簡更有效
