# 與寫作 Skill 的協作流程

## 核心原則：分工不分家

**寫作 Skill 主導內容靈魂，dom-seo 提供技術優化**

- **寫作 Skill 負責**：
  - 用戶的世界觀、價值觀、觀點
  - 語氣、說話方式、個人風格
  - 避免焦慮感、實事求是的表達
  - 內容的「為什麼要寫」、「想傳達什麼」

- **dom-seo Skill 負責**：
  - 結構建議（H2/H3 層級、段落組織）
  - 關鍵字自然融入位置
  - 技術檢查（Title、Meta Description、Schema Markup）
  - 內部連結建議
  - AI Overview 優化建議

**關鍵保證**：
- 內容 100% 是用戶的
- SEO 只是技術包裝層
- 用戶可以拒絕任何 SEO 建議
- **絕對不能讓 SEO 主導風格或改變用戶想說的話**

---

## 協作流程

### 階段 1：撰寫前規劃

**觸發時機**：用戶有內容主題，但尚未開始撰寫

**dom-seo 角色**：
1. 分析搜尋意圖（Informational / Transactional / Navigational）
2. 提供關鍵字策略（主要關鍵字 + LSI 關鍵字）
3. 建議文章結構大綱（H2/H3 層級）
4. 檢查是否為 YMYL 主題（需要更高 E-E-A-T 標準）

**寫作 Skill 角色**：
- 決定內容角度與觀點
- 確認哪些 SEO 建議符合用戶風格
- 拒絕不適合的結構建議

**範例對話**：
```
用戶：我想寫一篇關於「如何選擇適合的線上課程平台」的文章

寫作 Skill：
- 你想強調什麼角度？技術比較？使用體驗？還是避坑指南？
- 你的讀者是誰？創作者、企業、還是學習者？

dom-seo：
- 主要關鍵字：「線上課程平台」（月搜尋量 8,100）
- LSI 關鍵字：「課程平台比較」、「教學平台推薦」、「線上教學工具」
- 建議結構：
  H2: 為什麼選擇適合的平台很重要
  H2: 5 個關鍵評估標準
  H2: 3 大平台深度比較
  H2: 常見問題 FAQ
- 這不是 YMYL 主題，可以採用經驗分享語氣
```

---

### 階段 2：撰寫中優化

**觸發時機**：用戶已有初稿或正在撰寫

**dom-seo 角色**：
1. 檢查關鍵字自然度（不強制塞入）
2. 建議補充 FAQ 段落（針對 AI Overview）
3. 提醒缺少的內部連結機會
4. 建議可補充的數據/案例（增強 E-E-A-T）

**寫作 Skill 角色**：
- 維持用戶的說話語氣
- 確保補充內容符合用戶風格
- 決定是否採納數據建議

**範例對話**：
```
用戶初稿：
「選擇線上課程平台時，最重要的是平台穩定性。我之前用過某平台，結果上課到一半當機三次，學員體驗很差。」

dom-seo 建議：
- 「平台穩定性」可以自然提到「課程平台比較」（LSI 關鍵字）
- 建議補充：「根據 2024 年用戶滿意度調查，穩定性是創作者最在意的前三名因素」（E-E-A-T 強化）
- FAQ 建議：「如何測試平台穩定性？」

寫作 Skill 判斷：
- ✅ 採納 LSI 關鍵字建議（符合自然語氣）
- ✅ 採納數據補充（實事求是）
- ❌ 拒絕過度正式的表達（保持用戶口語化風格）
```

---

### 階段 3：撰寫後技術檢查

**觸發時機**：文章完成，準備發布前

**dom-seo 角色**：
1. 生成 Title Tag 與 Meta Description 建議
2. 生成 Schema Markup（Article / FAQ / HowTo）
3. 檢查內部連結是否完整
4. 檢查 H1/H2/H3 結構是否符合 SEO 最佳實踐
5. 提供 AI Overview 優化檢查清單

**寫作 Skill 角色**：
- 確認 Title/Meta Description 符合用戶風格
- 調整過於 SEO 化的用詞

**範例輸出**：
```
【技術 SEO 檢查】

Title Tag: 如何選擇適合的線上課程平台？5 個關鍵評估標準 | 創作者實戰經驗
Meta Description: 選課程平台別踩坑！從穩定性、金流、學員體驗等 5 大面向，分享 3 年實戰經驗。附平台比較表與常見問題解答。

Schema Markup (Article):
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "如何選擇適合的線上課程平台？",
  "author": {
    "@type": "Person",
    "name": "Cab"
  },
  "datePublished": "2026-02-23"
}

內部連結建議：
- 「課程定價策略」→ 連結到你之前的文章《線上課程定價完全指南》
- 「學員體驗設計」→ 連結到《提升課程完課率的 7 個技巧》

AI Overview 優化檢查：
✅ 有明確的問題解答（FAQ 段落）
✅ 包含結構化數據（Schema）
✅ 有實際經驗分享（E-E-A-T）
✅ 段落簡潔易讀（適合 AI 摘要）
```

## 品質保證機制

### 避免的陷阱

❌ **錯誤做法**：SEO 主導風格
```
原文：「我覺得這平台很爛」
SEO 過度優化：「根據課程平台比較研究，該平台在穩定性指標上表現不佳」
→ 失去用戶個人風格
```

✅ **正確做法**：保留風格，技術優化
```
原文：「我覺得這平台很爛」
寫作 Skill 調整：「這平台真的不行，上課當機三次」
dom-seo 補充：「（可在此段落自然提到"平台穩定性"關鍵字）」
最終輸出：「這平台的穩定性真的不行，上課當機三次」
→ 保留用戶語氣，自然融入關鍵字
```

### 使用者最終決定權

- 所有 SEO 建議都是**建議**，不是**指令**
- 用戶可以說「這個建議太 SEO 了，不採用」
- 寫作 Skill 有權否決任何違反用戶風格的 SEO 優化

## 載入時機

**自動載入情境**：
- 用戶提到「SEO」、「關鍵字」、「搜尋排名」
- 用戶要求「優化這篇文章給 Google」
- 用戶詢問「如何讓文章被 AI 引用」

**不應載入情境**：
- 純粹的個人創作（日記、隨筆、不發布的筆記）
- 用戶明確表示「不需要 SEO」
- 內容主題與搜尋無關（如內部文件、團隊公告）

---

## 與其他 Skill 的協作

- **method-course-article-writing**：撰寫課程 DLC 文章時，dom-seo 提供技術優化，但課程風格由 method-* 主導
- **social-post-optimizer**：社群貼文與 SEO 文章的優化邏輯不同，不混用
- **persona（Serin 人格）**：如果是 Serin 代筆，必須完全符合 Serin 的觀點與語氣

---

## 更新時機

當發現以下情況時，更新此協作流程文件：

1. 用戶反饋「這篇文章不像我寫的」→ 調整分工界線
2. 發現新的協作模式（如：與新 Skill 的搭配）
3. SEO 技術標準變化影響協作流程（如：AI Overview 演算法更新）
4. 累積足夠的成功/失敗案例，形成新的最佳實踐
