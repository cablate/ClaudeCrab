# 寫作流程迭代計畫

**建立日期**：2026-02-25
**綁定文件**：`knowledge/research/writing-workflow.md`
**目標**：讓產稿流程能跑，下周五前完成

---

## Cab 的意圖

建立一個「產稿」能力——電子報、貼文擴寫、講座大綱、部落格文章，只要是「要產出文字內容」的，都能用同一套流程。

## 為什麼選擇迭代而非重構

1. **比較簡單**——不用從零建一個大 skill，只要把現有的東西串起來
2. **不需要重構**——現有 skill 都在，只是沒串在一起
3. **邊做邊改**——串接過程中發現哪個 skill 有問題就直接改
4. **這是前置作業**——未來要建統整的寫作 skill，這次的串接就是基礎

## Cab 的原則

- **能跑 > 完美**
- **串接 > 重構**
- **邊做邊改 > 先規劃再動**
- **用現有的 > 從零建**

## 品質標準

Cab 要的產出必須：
- 架構清楚、手法到位
- 讓受眾感受到高價值
- 能帶流量、能讓人停下來看
- 看完能帶走東西
- 如果是部落格，要符合 SEO

## 具體做法

用 `writing-workflow-from-notes-to-blog.md` 當核心文件（調度中心），迭代它：

### 1. 補齊 skill 串接

| 步驟 | 對應 skill | 備註 |
|------|-----------|------|
| 釐清意圖 | `dom-brainstorming` | 素材明確時可快速帶過 |
| 載入風格 | `style-driven-author` | methodology 在 `.claude/skills/style-driven-author/author-style-methodology.md` |
| 補素材 | `WebSearch` | 只補事實背景 |
| 撰寫 | `style-driven-author` | 事前聲明 Core Persona + Tone |
| 品質檢驗 | 自查清單 + `social-post-optimizer`（社群）+ `dom-seo`（部落格） | 平台決定跑哪個 |
| 迭代 | 分段交付 | 每次修改重跑自查 |

### 2. 補齊產出類型分支

- **電子報初稿**：走哪些步驟、跳過哪些
- **講座大綱**：`lecture-design` 介入時機
- **貼文擴寫/重發**：舊貼文 → 新內容流程

### 3. 補齊最低標準

每種產出的「能跑就好」標準是什麼。

### 4. 邊做邊改

發現哪個 skill 有問題就直接改。
