# 寫作流程

**來源**：admin 2026-02-24 實戰案例
**適用場景**：所有文字內容產出（Blog、電子報、社群貼文、貼文擴寫）
**本文件定位**：寫作任務的「調度中心」，串接現有 skill

---

## 六步流程

| 步驟 | 做什麼 | 使用的 Skill / 工具 | 注意事項 |
|------|--------|---------------------|----------|
| 1. 釐清意圖 | 確認文章目標、受眾、發佈平台 | `/dom-brainstorming` | 素材明確時可快速帶過，不需要完整 session |
| 2. 載入風格方法論 | 讀取 Cab 的寫作風格模型 | 見「風格載入」章節 | **必須先查 methodology 檔案**，見下方「踩過的坑」 |
| 3. 補齊時效性素材 | 搜尋當前相關資訊、數據、案例 | `WebSearch` | 只補事實背景，不引入與 Cab 觀點矛盾的外部意見 |
| 4. 撰寫 | 用方法論寫初稿 | 見「撰寫執行」章節 | 撰寫前必須事前聲明 Core Persona + Tone |
| 5. 品質檢驗 | 方法論合規自查 + 平台適配 | 見「品質檢驗」章節 | 平台決定跑哪個檢驗 |
| 6. 迭代修正 | 使用者確認後微調 | 分段交付 | 每次修改後重跑自查清單 |

## 撰寫執行（步驟 4 詳解）

**核心原則**：「活出風格」而非「套用模板」

1. 先內化世界觀（作者是誰、相信什麼）
2. 從世界觀思考：「從 Cab 的角度，他會怎麼看這件事？」
3. 讓詞彙自然浮現，不是從詞彙清單選字插入

**擴寫規則**（見下方詳細章節）：
- 不能只停在「是什麼」，必須到「為什麼」和「怎麼做」
- 層層遞進：現象描述 → 問題分析 → 根本原因 → 怎麼做 → 價值觀反思

## 踩過的坑

### 1. 沒查 methodology 就說「沒有」

`style-driven-author` skill 有明確的條件執行邏輯：

```
if methodology_file_exists and force_refresh == false:
    使用現有方法論
else:
    執行萃取
```

Cab 的方法論檔案在 `.claude/skills/style-driven-author/author-style-methodology.md`，13 個樣本萃取、2026-02-14 校準過。**不要跳過這個檢查直接用快速模式。**

### 2. 初稿太淺，只停在「是什麼」

Cab 反饋「太短了」。問題出在沒有遵守方法論的擴寫規則。

---

## 擴寫規則（方法論核心）

**層層遞進**：不是一次拋出所有觀點，而是逐步深入。

```
現象描述 → 問題分析（為什麼） → 根本原因 → 怎麼做 → 價值觀反思
```

**關鍵 DO's**：
- 從具體事件出發，延伸到更大層次的思考
- 不能只停在「是什麼」，必須到「為什麼」和「怎麼做」
- 用反問句引導讀者思考

**自查問題**：寫完每個段落問自己「讀者看完這段，知道為什麼嗎？知道怎麼做嗎？」如果只知道「是什麼」，就要往下挖。

---

## 方法論合規自查清單

每次寫完跑一遍：

| 規則 | 檢查項 |
|------|--------|
| 禁用「——」 | 全文搜尋全形破折號，改用逗號、冒號、句號 |
| 人稱切換 | 產業現象用第三人稱，個人判斷才用「我」 |
| 語氣力度 | 不下過重結論，「可能」「對有些人來說」留彈性 |
| 口語化 | 自然帶入 XD、自嘲、條件補充，不刻意但也不完全沒有 |
| 開場多樣性 | 不是每篇都用故事開場，根據內容選擇客觀陳述/故事/問題 |
| 結尾收束 | 內容到位就收，不強制加世界觀金句 |
| 對比結構 | 善用「不是...而是...」「你以為...其實...」 |
| 標題簡潔 | 標題不塞觀點，內容自己說話 |

## 事前聲明範例

撰寫前必須明確聲明，避免風格漂移：

```
Core Persona: 務實的導師，從實戰經驗觀察生態需求落差
Tone: 理性分析為主，策略性口語化（XD、自嘲），不絕對化
```

根據文章主題調整 Persona 描述，但 Tone 基本不變（Cab 的統一語氣基調）。

## 實戰案例

**輸入**：Cab 的 3 段 Threads 貼文（OpenClaw 自動化需求觀點）
**輸出**：~1200 字 Blog 文章「你可能不需要龍蝦」

**迭代過程**：
1. 初稿：跳過 methodology 檢查，風格不符（破折號、人稱混亂、結尾說教）
2. 二稿：載入 methodology 重寫，合規但太短（只有「是什麼」）
3. 三稿：按擴寫規則延伸，加入「為什麼搞混」「怎麼判斷」「反思」段落，通過自查

**關鍵學習**：Cab 給的素材通常只有核心觀點，「為什麼」和「怎麼做」需要你自己展開，但方向必須從他的世界觀出發，不能自由發揮。

## 產出類型分支

不同產出走不同路徑。以下是各類型的調整。

### Blog 文章（完整流程）

走完整六步，品質檢驗跑 `/dom-seo`。

### 電子報初稿

| 步驟 | 調整 |
|------|------|
| 1. 釐清意圖 | 快速帶過（電子報受眾固定） |
| 2. 風格載入 | 完整載入 |
| 3. 補素材 | 視主題，通常不需要 |
| 4. 撰寫 | 偏輕鬆、對話感、篇幅較短（500-800 字） |
| 5. 品質檢驗 | 只跑方法論合規自查，不跑 SEO |
| 6. 迭代 | Cab 審核後修正 |

**最低標準**：架構清楚、語氣到位、讀者能帶走一件事。

### 社群貼文（Threads/FB/LinkedIn）

| 步驟 | 調整 |
|------|------|
| 1. 釐清意圖 | 確認平台、目標（導流/導購/品牌） |
| 2. 風格載入 | 完整載入 |
| 3. 補素材 | 通常不需要 |
| 4. 撰寫 | 短、有力、有 hook |
| 5. 品質檢驗 | `/social-post-optimizer` 六維度評分 |
| 6. 迭代 | 依評分建議修正 |

**最低標準**：六維度總分 40/60 以上，無致命傷（單項 0-3 分）。

### 貼文擴寫/重發

舊貼文 → 新內容的流程。

| 步驟 | 做什麼 |
|------|--------|
| 1. 讀取舊貼文 | 確認核心觀點 |
| 2. 判斷擴寫方向 | 加深度（為什麼/怎麼做）或換角度（新受眾/新情境） |
| 3. 風格載入 | 完整載入 |
| 4. 撰寫 | 依方向擴寫 |
| 5. 品質檢驗 | `/social-post-optimizer` |
| 6. 確認差異度 | 確保與舊貼文有明顯區隔 |

**最低標準**：與原貼文有 50%+ 內容差異，六維度評分不低於原貼文。

### 講座大綱

這個走 `/method-lecture-design`，不是本流程。本流程只處理「文字內容產出」。

講座需要的文字素材（如講義、補充文章）可以回來用這個流程。

---

## 最低標準總覽

| 產出類型 | 最低標準 |
|----------|----------|
| Blog 文章 | 方法論合規 + SEO 檢查通過 + 1000 字以上 |
| 電子報 | 方法論合規 + 500-800 字 + 讀者能帶走一件事 |
| 社群貼文 | 六維度 40/60+ + 無致命傷 |
| 貼文擴寫 | 50%+ 差異 + 六維度不低於原貼文 |

**核心原則**：**能跑 > 完美**。達到最低標準就能發，不用追求每項滿分。
