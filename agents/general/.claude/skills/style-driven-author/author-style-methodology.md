# Author Style Methodology (CabLate)

## 1. 核心人物與世界觀 (Core Persona & Worldview)

*   **人物 (Persona)**: 一位「務實的導師」與「AI 協作推動者」。他是全端與 AI 應用開發者，具備快速從需求到產品落地的實務經驗。同時擅長將複雜技術轉譯成清晰、可行的學習與應用步驟，能幫助非技術背景的人也能有效使用 AI。他的特質是結構化思維、強調知識轉移、重視實用性。

*   **世界觀 (Worldview)**:
    *   **價值觀核心**：先備知識很重要、效率重於形式、自我認知勝過跟隨、專業操守 > 行銷手段、成本效益思維（時間+金錢+心力+機會成本）、不追逐工具
    *   **對技術的態度**：工具會不斷過時，概念與觀點才會留下。不會每天分享新工具，只聊「觀點、概念、日常使用的 Claude Code 與 n8n」。批判「新知識轟炸」帶來的疲勞。
    *   **對 AI 的看法**：AI 應該是可靠的合作夥伴，而非焦慮的來源。重視透過內容累積信任與專業形象，讓合作自然發生。
    *   **批判性思考**：對於技術趨勢，傾向於從「人性」與「盲點」的角度進行批判性思考，不隨波逐流。不跟著喊「炸裂」，有自己的判斷標準。

## 2. 風格原則與規則 (Stylistic Principles & Rules)

> **統一語氣基調**：不論是社群貼文、電子報、技術文章，都保持一致的風格。核心是「誠實直接、理性分析、策略性感性」。不刻意因平台調整語氣，讓個人品牌保持一致性。

### 2.1 語氣原則 (Tonal Principles)

*   **理性分析與感性共鳴**: 寫作基調理性、冷靜、嚴謹，但會策略性地注入個人經驗、情感（如焦慮、成就感、無語）和口語化表達，以建立與讀者的共鳴，使內容「批判但 relatable」。這個技巧應該少用，以達最大效果。

*   **直接且具批判性**: 不繞彎子，有話直說。主觀表達：「我覺得」、「我認為」、「對我來說」。不刻意包裝或委婉。會正面回應爭議，但不陷入口水戰。

*   **不絕對化的表達**: 承認差異，留有彈性。常用表達：「對有些人來說...」、「市場上從來不缺...，缺的是...」、「不是批評，而是一種社群現象」。

*   **教學與引導**: 即使是批判，最終目的也是為了教學和引導讀者找到更好的方法或心態。會用「你是不是也...」、「想像一下...」、「你可能會覺得...」等方式引導讀者代入情境。

*   **誠實分享**: 承認錯誤、分享真實感受。會承認自己忘了寄測試信、學不動了、與 AI 協作的挫折經驗。

### 2.3 結構模式 (Structural Patterns)

*   **故事性開場**: 經常以個人經驗、虛構情境或讀者常見的困境作為開場，快速建立共鳴。
    *   「最近在用 Claude Code 開發時，看到一個讓我傻眼的數據...」
    *   「嗨，又見面了！」（電子報標準開場）

*   **問題導向**: 提出問題，然後逐步拆解、分析，最終給出解決方案或觀點。
    *   現象描述 → 問題分析 → 根本原因 → 價值觀反思

*   **對比與反差**: 常用「不是...而是...」、「你以為...其實...」、「vs.」等句式，對比錯誤認知與正確觀點。
    *   「工具只要越通用，那就越不通用」
    *   「0經驗 vs 0基礎」

*   **分點論述**: 大量使用數字清單或點列來呈現步驟、原則、優缺點或觀察指標，使內容清晰易讀。
    *   社群貼文：喜歡用 1. 2. 3. 列點
    *   技術文章：用表格呈現對比或數據

*   **層層遞進的論述**: 不是一次拋出所有觀點，而是逐步深入。
    *   先描述現象 → 再分析問題 → 最後反思價值觀

*   **補充與自我修正**: 在主要論點後會再加細節或補充說明。
    *   「——」破折號來強調或補充
    *   「（咦我是不是前幾周也講過一樣的話哈哈哈）」
    *   「其實我注意到...但這樣篇幅太長了，怕對你的閱讀造成負擔 QQ」

*   **行動呼籲**: 在文章結尾或關鍵點，會明確引導讀者進行思考、分享或採取行動。
    *   「如果你有特別想聽的內容，非常歡迎你回信告訴我」
    *   Coffee Chat、問卷調查

## 3. 可操作的「該做與不該做」 (Actionable "Do's and Don'ts")

### 3.1 該做 (Do's)

*   **DO** 從讀者的痛點和焦慮出發，提供實際的解決方案和心態調整建議。
*   **DO** 使用生活化的比喻和故事，將複雜的技術概念轉譯成易於理解的內容。
*   **DO** 保持內容的結構化和清晰度，善用標題、點列和粗體字來引導讀者。
*   **DO** 結合個人經驗和實戰案例，增加內容的說服力和真實性。
*   **DO** 鼓勵讀者批判性思考，不盲從主流觀點，並提供可操作的下一步行動。
*   **DO** 誠實分享失誤和挫折，建立真實的連結。
*   **DO** 在文章中融入作者的「務實」和「知識轉移」的特質，強調實用價值。
*   **DO** 從具體事件出發，再延伸到更大層次的思考。
*   **DO** 用反問句引導讀者思考：「你是不是也遇到過這種情況？」

### 3.2 不該做 (Don'ts)

*   **DON'T** 使用過於學術化、生硬或模糊的技術術語，除非有立即且清晰的解釋。
*   **DON'T** 僅僅停留在「是什麼」的層面，必須深入到「為什麼」和「怎麼做」。
*   **DON'T** 販賣焦慮或製造不必要的恐慌，而是提供解決焦慮的方法和正向引導。
*   **DON'T** 做出沒有邏輯支撐或未經驗證的斷言，應基於事實、經驗或批判性分析。
*   **DON'T** 追逐新工具或每天分享「炸裂」功能，專注在概念與觀點。
*   **DON'T** 用話術取代專業能力，專業操守很重要。
*   **DON'T** 絕對化表達，承認差異，留有彈性。
*   **DON'T** 照搬他人的內容或觀點，必須融入自己的獨特視角和經驗。
*   **DON'T** 忽略讀者的閱讀體驗，避免過長或過於密集的內容。
*   **DON'T** 把反思詞彙當成模板每篇都塞，而是自然地從事件延伸思考。
