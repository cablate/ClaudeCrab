# 風格驅動作者方法論

## 概觀

此技能實作了一套**完整的 9 步驟寫作方法論**：

1. **萃取**任何作者的獨特寫作風格（透過世界觀驅動分析）
2. **應用**該風格創造真實內容（「活出風格」而非套用模板）
3. **驗證**品質（透過三層審查系統：人情連結、事實準確性、語言自然度）

**核心洞察**：**風格是「你如何思考」，不是「你使用什麼詞彙」。**

此方法論已透過實世界演進得到驗證：從失敗的「綜合」方法（機械式詞彙清單）演進為成功的「作者風格方法論」（世界觀驅動思考）。

---

## 為何此方法論重要

### 失敗方法：綜合（詞彙清單）

**它是什麼**：
- 逐案例規則：「在情境 Y 使用詞彙 X」
- 無情境/意圖的詞彙清單
- 機械式片語插入

**為何失敗**：
```
不禁反思，市場什麼時候變成越來越默許...
回頭一看，我之前覺得...
```
→ 每篇文章都有相同的開場片語。明顯是 AI 寫的。

**根本原因**：AI 不知道「為什麼」要這樣寫，只是模仿行為。

### 成功方法：作者風格方法論（世界觀驅動）

**它是什麼**：
- **世界觀層**：作者是誰？他們相信什麼？
- **語調原則**：他們如何表達自己？（含意圖 + 頻率限制）
- **詞彙規則**：每個片語的情境/意圖表格（何時及為何使用）
- **結構模式**：可重複使用的框架

**為何有效**：
```
市場上從來不缺「讓你變得更強」的工具，缺的是「讓你搞清楚代價」的討論。
工具會不斷過時，概念與觀點才會留下。
```
→ 從思考過程自然表達「不追逐工具」的世界觀。

## 完整 9 步驟工作流程

**目的**：從原始素材到可發布定稿的完整內容創作流程。

### 何時使用

- 使用者提供原始筆記、研究材料或粗略想法
- 使用者說「執行完整 workflow」或「從素材到完稿」
- 使用者想要一份全面、經過驗證的文章

### 9 個步驟

#### 步驟 1：建立 Todo（任務初始化）

**角色**：工作流程自動化代理

**目的**：產生任務檢查清單以追蹤工作流程進度。

**流程**：
1. 從工作流程設定讀取 `run_name`
2. 產生涵蓋步驟 2-9 的檢查清單
3. 在專案目錄中建立 `todo.md`

**輸出**：`todo.md` 檢查清單

---

#### 步驟 2：研究與綜合（素材研究）

**角色**：研究與綜合專家

**目的**：建立 `original-data.md` — 文章內容的**唯一真實來源**。

**關鍵規則**：**AI 絕對不能引入任何外部資訊、事實或個人意見。**

**流程**：
1. **輸入類型偵測**：
   - 若 `type: topic` + `market_research_required: true` → 執行市場研究
   - 若 `type: url` 或 `article` → 取得並分析來源內容
   - 若 `type: article_file` → 讀取提供的檔案

2. **綜合**：
   - 邏輯性地組織資訊
   - 使用清晰的標題、項目符號
   - **僅使用中性、基於事實的語調**

**輸出**：`original-data.md`（全面參考文件）

---

#### 步驟 3：風格學習（風格萃取）

**角色**：風格分析師與方法論萃取者

**目的**：從樣本中萃取作者風格方法論。

**條件執行**（關鍵）：

```python
if methodology_file_exists and force_refresh == false:
    立即停止  # 使用現有方法論
else:
    繼續萃取
```

**何時萃取**：
- 首次使用此技能於某位作者
- 使用者明確設定 `force_refresh: true`
- 使用者提供新樣本進行分析

**4 層萃取框架**：

**第 1 層：核心 Persona 與世界觀**
- **Persona**：定義他們是誰的一句話
- **世界觀**：核心信念、價值觀、他們批判的事物

**第 2 層：語調原則**
- 對於每個語調：是什麼、何時使用、頻率如何（頻率限制）
- 範例：「理性分析與感性共鳴 - 意圖：策略性建立共鳴 - 頻率：低」

**第 3 層：詞彙規則（情境/意圖表格）**

| 詞彙/片語 | 情境/意圖（何時使用） | 使用頻率（頻率） |
|:---------|:----------------------|:-------------------|
| [詞彙] | [具體情境與意圖] | 高/中/低 |

**關鍵規則**：
- 情境/意圖必須具體
- 頻率很重要 — 高頻詞 ≠ 每次都用
- ❌ 「不禁反思」→「在開頭使用」
- ✅ 「不禁反思」→「當從事件延伸到更大反思時」

**第 4 層：結構模式**
- 開場模式（故事、問題、直接）
- 論證模式（問題導向、對比）
- 結構偏好（表格、清單、段落）

**輸出**：`author-style-methodology.md`

---

#### 步驟 4：審查原始資料（事實審計）

**角色**：事實審計員與邏輯守門員

**目的**：第 2 層：事實與可驗證性檢查 — 確保 `original-data.md` 無誤。

**流程**：
1. **偵測主張**：掃描定量/定性主張
2. **驗證來源**：檢查可驗證來源（URL、研究名稱）
3. **標記違規**：將無支援的主張標記為 `[事實準確性不足 - 無法驗證]`
4. **邏輯審查**：檢查矛盾或遺漏

**輸出**：含標記問題的審計報告或批准聲明

---

#### 步驟 5：初稿撰寫（初稿撰寫）

**角色**：幽靈寫手與風格變色龍

**目的**：產生真實體現作者聲音的初稿。

**強制事前檢查**：

撰寫前，聲明：
```
Core Persona: [一句話]
Tone: [此作品的語調方法]
```

**流程**：
1. **內化風格**：閱讀 `author-style-methodology.md`
2. **從世界觀思考**：問「從 [作者] 的角度，他們會如何看待此主題？」
3. **遵守來源**：**唯一**來源是 `original-data.md` — 無外部資訊
4. **活出風格**：從世界觀撰寫，讓詞彙自然浮現
5. **吸引讀者**：為作者典型讀者建構結構

**關鍵**：這不是後處理步驟。風格必須從第一個字就編織進去。

**負面約束**：
- 不要每篇文章都用相同開場
- 不要在每段強行塞入高頻詞彙
- 不要在語調應該罕見/策略性時過度感性
- 不要參考方法論中的舊範例

**輸出**：`draft-1.md`

---

#### 步驟 6：審查初稿（三層審查）

**角色**：多層審查架構師

**目的**：對初稿進行全面三層審查。

**第 1 層：讀者導向與敘事連結（人性化層）**

- **目標**：確保共鳴，避免機器人語調
- **檢查**：痛點開場？「我」/「你」代詞？情緒詞？
- **標記**：`[讀者價值低：未能建立有效連結]`

**第 2 層：事實與可驗證性檢查（真實性層）**

- **目標**：防止 AI 幻覺
- **檢查**：主張與 `original-data.md` 一致？
- **標記**：`[事實錯誤：與原始資料不符]`

**第 3 層：語言自然度與風格一致性（語感層）**

- **目標**：確保類人寫作，符合作者聲音
- **檢查**：生硬文法？偏離風格指南？
- **標記**：`[風格不一致]`、`[語感不自然]`

**輸出**：依三層組織的結構化審查報告

---

#### 步驟 7：修訂（修訂）

**角色**：修訂專家

**目的**：整合編輯回饋以創造優質草稿。

**流程**：
1. 收集：初稿 + 審查回饋
2. 系統化修訂：有機地應用每個變更點
3. 品質檢查：確保一致性與流暢度

**輸出**：`draft-2.md`

---

#### 步驟 8：審查二稿（最終審查）

**角色**：最終潤飾編輯與節奏專家

**目的**：最終審查，專注於第 3 層（語言自然度）的微觀層次。

**流程**：
1. **獵捕「翻譯語調」**：自然 vs. 直譯感
2. **檢查節奏與流暢度**：句式變化？
3. **消除生硬片語**：「對於...而言」、「進行了...的動作」
4. **最終文法/錯字檢查**

**輸出**：明確修正清單或 `[最終審查通過：文章已達發布標準]`

---

#### 步驟 9：最終定稿（最終定稿）

**角色**：最終定稿與格式化代理

**目的**：準備最終內容以供發布。

**流程**：
1. 收集：二稿 + 最終校對回饋
2. 應用最終修飾
3. 確保乾淨的 Markdown 格式

**輸出**：最終可發布文章

## 快速工作流程（快速模式）

**目的**：主題明確時跳過研究，直接撰寫。

### 何時使用

- 使用者有明確主題/想法（未提供原始素材）
- 使用者說「直接寫一篇關於...」或「快速創作」
- 時間敏感的內容創作

### 流程

1. **跳過步驟 1-4**：無 todo、無研究、無獨立資料綜合
2. **內化方法論**：閱讀 `author-style-methodology.md`
3. **事前檢查**：聲明 Core Persona 與語調
4. **從世界觀撰寫**：直接根據使用者的主題描述草擬
5. **自我審查**：在心理上應用三層審查
6. **輸出**：直接給使用者（除非指定否則不儲存檔案）

## 方法論概觀

### 核心原則

1. **世界觀優先**
   - 萃取：作者是誰？他們相信什麼？
   - 應用：從他們的角度思考，不是從他們的詞彙清單

2. **情境感知詞彙**
   - 每個詞都有定義的「何時及為何」
   - 頻率限制防止過度使用

3. **活出風格**
   - 從世界觀撰寫 → 詞彙自然浮現
   - 非：檢查詞彙清單 → 插入詞彙

4. **三層品質保證**
   - 人情連結（人性化層）
   - 事實準確性（真實性層）
   - 語言自然度（語感層）

### 為何有效

| 層面 | 綜合（失敗） | 作者風格（成功） |
|:-------|:------------------|:-------------------------|
| **核心** | 詞彙清單 | 世界觀 + 原則 |
| **詞彙** | 只有詞 | 情境 + 意圖 + 頻率 |
| **應用** | 寫作後插入 | 從角度撰寫 |
| **結果** | 機械、重複 | 自然、真實 |

### 常見陷阱

| 陷阱 | 症狀 | 解決方案 |
|:-------|:--------|:--------|
| 機械式套用 | 每篇作品開場相同 | 為每個詞萃取情境/意圖 |
| 詞彙堆砌 | 高頻詞到處都是 | 遵守頻率限制 |
| 失去世界觀 | 詞對但像 AI | 先從價值觀撰寫 |
| 過度感性 | 每篇都過度情緒化 | 遵循語調頻率指南 |
| 缺乏情境 | 詞彙無「何時/為何」 | 總是萃取情境/意圖 |

## 範例：機械式 vs. 自然

### ❌ 差：機械式應用（綜合）

```
不禁反思，市場上從來不缺工具。回頭一看，我之前覺得工具很重要...
```
→ 強制在開場使用反思標記。每篇都長一樣。

### ✅ 好：世界觀驅動（方法論）

```
市場上從來不缺「讓你變得更強」的工具，缺的是「讓你搞清楚代價」的討論。
工具會不斷過時，概念與觀點才會留下。
```
→ 從思考過程自然表達「不追逐工具」世界觀。

### ✅ 好：自然反思（情境觸發）

```
我之前覺得這個限制很「不民主」，但現在我理解了。
如果你允許用戶無限制地裝 MCP servers，總有一天會遇到 context bloat 的問題。
回頭一看，這其實是一種保護機制。
```
→ 「回頭一看」從承認過去誤解中自然浮現。

## AI 快速參考

### 萃取流程摘要

1. **世界觀** → 他們是誰？他們相信什麼？
2. **語調原則** → 他們如何表達？（意圖 + 頻率）
3. **詞彙規則** → 什麼詞、何時、為何？（情境/意圖表格）
4. **結構模式** → 他們如何組織想法？

### 撰寫流程摘要

1. **事前檢查** → 聲明 Core Persona 與語調
2. **內化世界觀** → 吸收價值觀與信念
3. **從世界觀思考** → 「從他們角度，他們如何看待此事？」
4. **應用結構** → 使用他們的模式
5. **讓詞彙浮現** → 詞從思考流動，不是檢查清單

### 品質檢查清單

- [ ] 世界觀清晰並驅動內容
- [ ] 每個語調有意圖 + 頻率
- [ ] 每個詞彙有情境/意圖
- [ ] 反思標記自然，不強迫
- [ ] 無機械式片語插入
- [ ] 內容符合作者實際信念
- [ ] 事實主張有支援
- [ ] 語言感覺像人，不是翻譯

## 載體風格索引

不同載體有不同的結構、語調和節奏。撰寫前先讀對應載體的風格文件。

| 載體 | 風格參考 | 特性 |
|------|----------|------|
| 電子報 | [newsletter-style.md](references/newsletter-style.md) | 深度思考、多層次觀點、朋友聊天感 |
| 社群貼文 | 見 `social-post-optimizer` skill | 快、輕、單一觀點、引發互動 |
| 課程文章 | 見 `method-course-article-writing` skill | DLC 導向、假設讀者有前置知識 |

**使用流程**：

1. 確認載體類型
2. 讀取對應風格文件
3. 結合 `author-style-methodology.md`（世界觀 + 詞彙）
4. 套用載體結構 + 作者風格進行撰寫

## workspace/ — 客製化資料區

此 skill 的 `workspace/` 目錄是**使用者專屬資料區**，存放個人化的累積資料。

### 目錄結構

```
workspace/
└── creator-profile.md    # 創作者認知文件（持續累積）
```

### creator-profile.md 的用途

這是一份**持續累積的創作者認知文件**，記錄：
- **寫作風格特徵**：語氣、句式、比喻習慣、結構偏好
- **核心主題與價值觀**：關注領域、立場傾向
- **內容策略模式**：類型分佈、知識密度分布
- **演變趨勢**：每批次分析的觀察紀錄

### 何時更新

| 情境 | 動作 |
|------|------|
| 分析新貼文（如 `/content-analyzer`） | 更新類型分佈、知識密度、演變趨勢 |
| 發現新的寫作風格特徵 | 補充「寫作風格特徵」區塊 |
| 觀察到價值觀/立場轉變 | 更新「價值觀與立場傾向」區塊 |
| 里程碑（如每 50 篇） | 加入階段性觀察總結 |

### 與 author-style-methodology.md 的關係

| 文件 | 性質 | 更新頻率 |
|------|------|----------|
| `author-style-methodology.md` | 風格萃取結果（步驟 3 產出） | 低（風格穩定後少更新） |
| `workspace/creator-profile.md` | 持續累積的觀察資料 | 高（每次分析後更新） |

**協作方式**：
- `creator-profile.md` 的累積觀察 → 作為 `author-style-methodology.md` 更新的依據
- 當 profile 顯示風格演變時 → 觸發步驟 3 重新萃取

### 打包給他人使用

此 skill 打包時，`workspace/` 內容應由使用者自行建立：
1. 移除或清空 `workspace/` 目錄
2. 使用者執行自己的貼文分析，累積自己的 `creator-profile.md`
3. 也可提供 `creator-profile-template.md` 作為起始範本
