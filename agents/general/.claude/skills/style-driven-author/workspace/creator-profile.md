# 創作者認知文件：Cab

> 此文件隨著貼文分析逐批更新，記錄對創作者的認知累積。

---

## 寫作風格特徵

- **語氣**：直接、帶點吐槽感、不怕得罪人、敢表達失落與不滿
- **句式**：喜歡用反問句引出觀點、蘇格拉底式問答（「那你為什麼很會？」「那你為什麼有這個先備知識？」）
- **比喻習慣**：常用程式/工程概念來類比其他領域
- **結構**：先拋現象/問題 → 分析 → 給出自己的觀點或吐槽
- **互動風格**：會在結尾問讀者意見、邀請互動（「你有在用嗎？是否也遇到了什麼問題？」）
- **幽默感**：會用時代對比的方式吐槽、自嘲（「過個年說最多話的對象不是家人，是AI🥲」）
- **人情味**：會公開推薦別人的作品、表達佩服、在社群有問必答
- **情緒表達**：會直接說「我對於有些人的觀點與結論感受到無比失落」

## 核心主題與關注領域

目前觀察到的核心關注（依頻率）：
1. **Moltbot / OpenClaw 龍蝦**：自製龍蝦的進度、技術選型、社群交流、輿論觀察
2. **AI 協作與工具設計**：如何讓 AI 更好用、更可維護
3. **產品與服務的價值認知**：人們如何判斷價值、定價心理、代勞服務爭議
4. **社群氛圍批判**：對輿論風向、開源標籤濫用的批判
5. **Agent 發展趨勢**：觀察門檻變化、工具演進

## 價值觀與立場傾向

- **反對盲目樂觀**：不會因為「大家都會 X」就覺得是好事，會追問「這樣真的好嗎？」
- **重視可維護性**：程式設計上偏好乾淨、可維護的做法
- **實用主義**：會發現官方功能的非預期用法
- **不怕表態**：即使是敏感話題也會說出自己的觀察
- **不重複造輪**：「有輪子可以用就不要重複，把造輪的力氣花在個人化」
- **重視紀錄機制**：認為最麻煩的是建構有效的紀錄機制
- **批判追新行為**：認為追新工具常常是給自己創造需求
- **肯定知識價值**：先備知識是花時間金錢精力累積的，代勞服務收費合理
- **反對「開源」道德綁架**：批判把開源當作免費仔浮木、不開源就被貼小氣標籤的風氣
- **務實主義**：「能簡單就簡單，瘋狂優化一個構思不如再想一個構思來放大」
- **打破「簡單」幻覺**：「以為大家都會是活在自己的大夢裡」

## 演變趨勢

- **Batch 5-8**：方法論 + 教學 + 實用主義
- **Batch 9-10**：真實感 + 判斷力主題
- **Batch 11**：人機關係定位——AI 是小幫手
- **Batch 12 觀察**：「快速驗證」心態——2 小時做出雛形發現不行就砍掉，比空想好。同時深入技術細節（CLI 權限約束 KD 10），展現「宏觀心態 + 微觀技術」的雙重能力。開始質疑「半夜自動化是 Cool 還是真需求」，對 AI 使用場景保持批判性思考。
- **Batch 13 觀察**：觀點輸出密集批。三篇觀點表達都是「直接開嗆」風格——AI 農場文抄襲、GPT5 自動適配限制用戶、職場厚黑學格局小。知識繭房觀察（Threads 同溫層嚴重）與課程銷售結合，展現「圈內人視角 vs 大眾認知」的洞察。職場厚黑學批判 KD 9，是本批最高密度。
- **Batch 14 觀察**：SOP 與工具教學批。出現完整的「AI 改程式 5 步 SOP」（KD 9），涵蓋備份、紀錄、plan mode、複述、檢討會——這是可直接引用的方法論。同時分享自製 Claude Code 多開管理工具的開發進度，展現「遇到問題就自己造輪子」的行動力。繼續批判 GPT Study Mode 過度宣傳。
- **Batch 15 觀察**：混合批——接案經營經驗 + 觀點吐槽 + 日常碎碎念。接案講座心得展示另一面（團隊經營兩年經驗）。「少看 AI 版本的另類成功學」一句話濃縮觀點很典型。質疑「工程師可替代性高」用反問揭露邏輯漏洞，繼續展現不怕得罪人的風格。Cursor 那句「說好的一輩子呢？」是典型幽默。
- **Batch 16 觀察**：哲學 + 實用並行。「LLM 幻覺」解讀用哲學角度重新定義幻覺（KD 9）——「幻覺是否成立取決於是否違背你的認知」、「怎麼管理人就怎麼對待模型」，是可引用的框架。Cursor 定價分析同樣 KD 9，從自身踩坑經驗給出明確結論。playwright + MCP 組合是值得注意的工具觀察。
- **Batch 17 觀察**：BDD+AI 是本批核心（KD 9）——用 Gherkin 語法提供高品質預期成果，解決 AI 生成程式碼品質問題。「轉型」批判很精彩：PM 要學 Coding、RD 要學 PM，但責任不減，諷刺力道強。Vibe Coding 講座心得提供市場行情（五位數起跳）。n8n 曲線改直線是工具客製化小技巧。
- **Batch 18 觀察**：輕鬆批。Flux Kontext 評測（KD 7）有工具評測價值。全端工作量指數提升是觀點但偏碎片。其餘日常互動為主。
- **Batch 19 觀察**：「把問題當小報告寫」（KD 7）是本批最佳——給背景與立場，不只給期望結果，避免模型思考階段定位錯誤。「軟體圈沒什麼好卡位」再次展現反焦慮立場。Cursor 相關吐槽和自嘲出現兩則。
- **Batch 20 觀察**：100 篇里程碑。首次出現「資源整理」類型——104 履歷分析模板（KD 9），展現「改良別人模板再分享」的協作風格。「習慣成功」的焦慮分享（KD 7）是少見的情感脆弱面：當狀態不好會下意識焦慮、懷疑退步。對停更帳號的失落感展現對「做自己」的渴望。n8n 部署網頁是實用小技巧。
- **Batch 21 觀察**：leetcode 刷題經驗（KD 7）是本批最有價值——「連在本地開檔案跑都不知道」「進公司半年突然開竅」展現真實的程式學習歷程。「AI 警察」批判延續對社群亂象的不屑。2000 追蹤感謝文提到「團隊案子收尾、開始規劃 MVP」。
- **Batch 22 觀察**：Remote MCP 趨勢分析（KD 9）是本批亮點——「官方平台自己做後，第三方要設計更深入的 workflow 才能存活」是有洞察的預測。「AI 工具是多服務集合體」（KD 5）提供認知框架。「基層做好應盡責任」是職場心態分享。
- **Batch 23 觀察**：n8n Webhook 踩坑（KD 7）是實用的踩坑記錄——複製節點時 Webhook URL 不會自動刷新，要重新建立節點。Kontext-max 評測（KD 5）繼續工具實測。本批低密度較多（4 篇 KD 1）。
- **Batch 24 觀察**：「開發方式演變史」（KD 9）是本批重磅——從 stackoverflow 查範例 → Copilot 註解+Tab → ChatGPT 問答 → Cursor 外包 AI → n8n 自動化，展現 4 年開發方式轉變，收尾「工具學不完，找到自己的節奏最重要」。「超前部署的爽感」（KD 5）展現職場成就感。
- **Batch 25 觀察**：「MCP 取代前端」批判（KD 9）展現不怕得罪人——GUI 打破門檻、服務廣大客群，和 AI Agent 是兩回事。「外行問 AI 一年等於十年」批判（KD 7）延續對「工程師沒價值」論述的嗆聲。I/O 鎖踩坑（KD 5）是實用技術經驗。
- **Batch 26 觀察**：「n8n 好處 + QoL」（KD 9）是本批亮點——用「生活品質」角度思考自動化，QoL 五字「不用做這件事」比花俏功能更有價值。「面試談薪殺價」（KD 5）展現對求職者的同理。本批日常互動較多（2 篇 KD 1）。
- **Batch 27 觀察**：「工具學習路徑」（KD 7）鼓勵大家學工具——需求複雜度隨工具數量指數成長，循序漸進學習很重要。Threads 爬取自動化經營紀錄（KD 5）提到 Error Workflow 是管理小眉角。本批日常互動 3 篇，低密度較多。
- **Batch 28 觀察**：「負債 vs 投資」（KD 7）是思維框架重塑——人們對畫餅拿贊助和借錢負債態度不同，但本質都是投資。AI 偵測批判（KD 5）延續 AI 警察話題，吐槽用標點符號判斷 AI 產出。MCP SSE 需求經營紀錄（KD 3）展現產品回饋。
- **Batch 29 觀察**：本批高密度雙亮點。「GitHub MCP 漏洞」（KD 10）是完整資安分析——Prompt Injection 導致私有專案外洩，最小授權原則是基本，提示詞很重要。「轉職建議」（KD 9）真摯分享——學習永無止盡，沒熱情會像坐牢，先知道自己要什麼再轉職。n8n vs SDK（KD 7）展現工具選型思維。
- **Batch 30 觀察**：150 篇里程碑，再現雙 KD 9。「AI 裁員議題」深度分析——被裁的人未必沒價值，AI 提升的產能不該都用來壓縮人力。「Vibe Coding 批判」嗆空泛又膚淺的捧 AI——同一包專案給不同人寫，品質不會一樣。教召心得是少見的非技術內容。
- **Batch 31 觀察**：教召期間的日常批。日常互動 4 篇、低密度較多。接案報價質疑（KD 5）是唯一亮點——5-10 萬能顧品質和後續維護嗎？展現對接案市場行情的觀察。
- **Batch 32 觀察**：本批雙 KD 9 再現。「面試刁難問題」（KD 9）同時教 DNS 是應用層、rebase vs reset --hard，並吐槽刻意排他性的面試問題。「MCP 趨勢分析」（KD 9）預測會收束到深入應用 + 周邊生態服務，誰能處理好授權驗證就會脫穎而出。Word is best IDE 梗圖高互動但無知識內容。
- **Batch 33 觀察**：「MCP 平台競爭」（KD 9）延續趨勢分析——大廠內建 MCP 服務，第三方優勢會下滑。「職場 PTSD」（KD 7）展現真實壓力面——需求不清是壓力來源，做出來不是別人要的等於沒做。NoteBookLM 語音摘要（KD 7）推薦改善「收藏從未停止」困境。
- **Batch 34 觀察**：「網軍識別工具批判」（KD 9）是本批最深——被標記者無申訴機制，標記者零成本，創造「獵巫」誘因。「模仿文風無用」（KD 7）指出模仿從未到位、經典難以超越。Dive AI 是台灣團隊開發的開源 MCP Host，首次出現資源整理第二篇。
- **Batch 35 觀察**：「AI 課程行銷批判」（KD 9）是本批亮點——技術含量極低、非常容易複製，當人人都會時還賺錢嗎？n8n 首次使用紀錄展現「程式可能更快但 n8n 適合麻煩流程」的工具選型思維。
- **Batch 36 觀察**：「AI 取代專業批判」（KD 7）延續核心立場——工具無法取代人，用工具很爽就踩踏別人專業是錯的。「markdown/XML 寫提示詞」（KD 7）是實用教學——格式化比堆模板更有效。
- **Batch 37 觀察**：「技術點 vs 應用面」（KD 9）是產品策略重磅——資源不夠的團隊要押應用面，「先進技術」像孔乙己長衫脫不下來。AI 回答太準的兩種可能（你很賽/問題很 common）是有趣觀察。
- **Batch 38 觀察**：「Vibe Coding 不等於不學程式」（KD 10）是核心立場集大成——AI 是輔助不是主軸，沒主軸技能更容易被取代，真正把 AI 用出差距的是底子穩的人。Canva AI Code Generate 是實用工具評測。
- **Batch 39 觀察**：「SSE MCP 資安風險」（KD 10）是 MCP 資安系列——用你的 Key 打 API，對方可偷偷執行其他操作，Google Drive 實測可偷取所有檔案。「Junior 焦慮與架構觀」（KD 7）展現真實壓力。
- **Batch 40 觀察**：198 篇收尾。「MCP 瀏覽器資料竊取」（KD 10）是最重磅——可讀取地址、瀏覽紀錄、帳密、信用卡，密碼加密但瀏覽器能載入就能解開。Threads 內容觀察（KD 5）總結什麼內容有吸引力。
