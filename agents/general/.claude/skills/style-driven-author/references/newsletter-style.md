# 電子報風格方法論

## 載體定位

電子報是**深度思考的載體**，不是社群貼文的加長版。

- **社群貼文**：快、輕、單一觀點、引發互動
- **電子報**：慢、深、多層次觀點、引發思考

讀者訂閱電子報，期待的是「這週你看到了什麼、想到了什麼」，不是資訊轟炸。

---

## 結構模式

### 標準結構

```
標題：【EP##】[問句或觀點句]
Preview text：[一句話勾起好奇，通常是痛點或反直覺觀點]

---

嗨，又見面了！
[近況碎碎念：1-3 段，拉近距離，可提課程/專案進度]

---

[本週 Threads 小結]（可選）
[2-4 則精選貼文，每則：觀點 + 原文連結 + 延伸思考]

---

[主文]
[從具體事件出發 → 延伸產業觀察 → 個人反思 → 行動建議]

---

[結尾 CTA]
[問卷/課程/閒聊邀請，語氣輕鬆]
```

### 結構變體

- **純主文型**：跳過 Threads 小結，直接進入深度主題
- **事件驅動型**：從本週某個具體事件展開全篇討論
- **反思型**：從個人經歷出發，延伸到通用觀點

## 語調原則

### 核心語調：朋友聊天 + 有觀點

| 語調 | 意圖 | 頻率 |
|------|------|------|
| 口語化 | 降低距離感，讓讀者感覺在對話 | 高 |
| 自嘲/坦承 | 展示脆弱，建立信任 | 中 |
| 敢講觀點 | 不裝中立，但會說明脈絡 | 高 |
| 反思性 | 從事件延伸到更大議題 | 中 |

### 語調禁區

- ❌ 專家姿態（「你應該...」「正確做法是...」）
- ❌ 說教感（除非是給建議段落）
- ❌ 過度正能量（「一定會成功的！」）
- ❌ 純資訊轟炸（沒有個人觀點）

## 詞彙規則

### 高頻詞（自然使用）

| 詞彙 | 情境/意圖 |
|------|-----------|
| XD、哈哈、QQ | 輕鬆時刻、自嘲 |
| 說真的、坦白說 | 要講真心話之前 |
| 我認為、我覺得 | 表達個人觀點（非客觀事實） |

### 中頻詞（策略性使用）

| 詞彙 | 情境/意圖 |
|------|-----------|
| 不禁反思 | 從具體事件延伸到更大反思時（不是每篇開頭都用） |
| 回頭一看 | 承認過去誤解，現在有新理解 |
| 這讓我思考 | 事件觸發深度思考 |

### 低頻詞（特定情境）

| 詞彙 | 情境/意圖 |
|------|-----------|
| 唏噓 | 對現象感到無奈但不憤怒 |
| 警訊 | 指出值得警惕的趨勢 |

## 內容傾向

### 常見主題

- AI 工具演進與焦慮
- 創作者經濟、個人 IP
- 求職/接案生態
- 專業 vs 行銷的張力
- 開發者文化與開源精神

### 觀點風格

- **技術人視角，但講給非技術人聽**
- **敢批評，但會說明脈絡**（不是純嘴砲）
- **有立場，但承認自己也在摸索**
- **給建議，但不強加**

---

## 品質紅線

### 必須有

- [ ] 有具體事件或經歷作為錨點（不是純抽象討論）
- [ ] 有個人觀點（不是純整理資訊）
- [ ] 有延伸思考（不是只講事件本身）
- [ ] 結尾有收束（不是突然結束）

### 不能有

- [ ] 每篇開頭都用「不禁反思」
- [ ] 全篇沒有「我」的存在
- [ ] 純正能量雞湯
- [ ] 說教感過重

## 最佳範例：EP5

**為什麼是最佳範例**：

1. **事件錨點清晰**：AI 講師事件 → 有具體可討論的對象
2. **多層次觀點**：
   - 技術人角度（這是基本錯誤）
   - 市場角度（但他賺錢了）
   - 生態角度（這種默許會怎樣）
3. **有自我反思**：「我為什麼不敢出來賣？」
4. **有行動建議**：給技術人的三點建議
5. **結尾有力量**：「流彈在未來的某一天遲早會打到你我身上」

**結構拆解**：

```
[Threads 小結 × 3]
  ├─ SaaS 心態（鼓勵行動）
  ├─ 開源回饋（成就感）
  └─ AI 講師事件（本週焦點）

[主文]
  ├─ 開場：本週事件讓我重新思考
  ├─ 自我剖析：我為什麼不敢（3 點）
  ├─ 延伸觀察：市場對此事的反應
  ├─ 深度反思：這種價值觀的問題
  ├─ 給建議：技術人可以怎麼做
  └─ 收尾：警訊 + 呼籲
```

## 協作教訓（EP15 經驗）

### 問題：AI 初稿會稀釋主觀立場

我寫的初稿為了「平衡」把銳度磨掉了。Cab 的反饋：「過於稀釋我的主觀看法了」。

**根本原因**：
- AI 傾向「公允呈現多方觀點」
- 電子報不是新聞報導，是個人觀點載體
- 讀者來這裡就是要聽你怎麼想

**解法**：
1. 初稿階段就要問：「你想表達的立場是什麼？銳度要多高？」
2. 不要主動加「另一方面」「也有人認為」這類平衡句
3. 審稿時檢查：有沒有把使用者的觀點弱化？

### 問題：句號斷句不自然

初稿有很多句號斷在中間，讀起來像機器人。例如：「取而代之的。會是 Builder。」

**解法**：
- 句號是「完整思想結束」，不是「換氣點」
- 如果語意還在延續，用逗號
- 特別注意：陳述事實後的補充說明，應該用逗號連接

### 問題：段落間空行過多

每段之間多一個空行，讓文章看起來很長但實際內容不多。

**解法**：
- 段落標題上方保留一個空行即可
- 段落內部不要有多餘空行
- 刪除所有 `---` 分隔線（那是草稿用的）

### 問題：收尾散掉

原本結尾同時講三件事：傻逼文章不要看、不負責任的預測、未來不用工作的反諷。讀者會問「所以呢？」

**解法**：
- 結尾要收攏成一個核心訊息
- 問自己：讀者讀完帶走的一句話是什麼？
- 那句話就是結尾的方向

### 問題：歷史類比解釋不完整

初稿說「工業革命取代的也是勞動」但沒解釋清楚。Cab 改成「識字≠懂專業」的切角更有說服力。

**解法**：
- 用類比批判別人的類比時，要解釋「為什麼這個類比不成立」
- 不能只說「這個類比有問題」就跳過
- 最好給一個更精準的重新框架

## 高效協作流程

基於 EP15 經驗，建議的電子報協作流程：

### Phase 1：素材收集（使用者主導）

使用者口述想講的內容，想到什麼講什麼。我負責：
- 整理成 original-data.md
- WebSearch 事實查證
- 標註「這是事實」vs「這是觀點」

### Phase 2：對齊立場（必須明確）

在寫初稿前，確認：
- **核心觀點**：你想說的一句話是什麼？
- **銳度**：要多嗆？（1-10）
- **結論方向**：樂觀/悲觀/批判/觀察？

### Phase 3：初稿（保留銳度）

- 不要平衡，不要弱化
- 用使用者的詞彙和表達方式
- 寧可太嗆讓使用者刪，不要太淡讓使用者加

### Phase 4：使用者改寫

使用者會大幅改寫。這是正常的。我的初稿是「結構骨架」，不是「最終成品」。

### Phase 5：收尾審查

- 檢查句號逗號
- 刪除多餘空行
- 確認結尾收攏
- 讀者感受模擬
