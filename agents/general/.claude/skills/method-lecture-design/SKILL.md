# Lecture Design 講座/課程設計方法論

## ⚠️ 與 Cab 合作的操作流程（必讀）

**在開始任何內容製作之前，必須遵循這個流程：**

```
1. Cab 先講想像（5 分鐘）
   → 這週/這篇想怎麼講、切什麼角度、哪些素材一定用、哪些省略
   
2. 我問問題確認
   → 「這個觀念要獨立講還是融進去？」
   → 「案例帶現成的還是現場設計？」
   → 「這段你想要什麼感覺？」

3. 對齊後我才展開

4. 展開完給 Cab 審
```

**為什麼**：我埋頭做完才給你看 → 方向錯 → 修正比從頭來還累。你先講、我問、對齊、再做，在最前面就抓到分歧。

**紅線**：
- ❌ 沒問 Cab 想像就開始做
- ❌ 沒讀既有素材就展開（素材是血肉，課綱是骨架）
- ❌ 用自己發明的框架取代 Cab 已有的觀念
- ❌ 自己加段落、改結構而不確認

## 通用原則（跨情境可用）

這些原則不只適用於課程，也適用於**文章、電子報、影片腳本**。差異只在形式限制。

| 原則 | 課程 | 文章 | 電子報 | 影片 |
|------|------|------|--------|------|
| 認知負荷管理 | 每 25 分鐘休息 | 每段一個概念 | 一封一重點 | 短影音 < 60 秒 |
| 情緒曲線 | HOOK→震撼→驗證→安心 | 開頭抓痛點→解法→收尾 | 標題決定開不開 | 前 3 秒定生死 |
| 三層結構 | 觀念→方法→實作 | Why→How→What | 問題→解法→行動 | Hook→內容→CTA |
| 記憶點設計 | 金句、重複、呼應 | 金句、標題 | 一句話摘要 | 重複 loop |
| 比喻優先 | 技術用生活比喻 | 同 | 同 | 同 |

**核心共通**：讓人「帶走東西」，不是「看完就忘」。

## 核心原則（課程專用）

**講座不是資訊傳遞，是認知轉變。**

三個檢驗標準：
1. **邏輯自洽**：從「為什麼」到「怎麼做」到「用在哪」，流程自然
2. **記憶點清晰**：學員離開時能記住 2-3 個核心概念
3. **情緒正向**：學員帶著「安心」或「期待」離開，而非焦慮

## 工作流程

### Mode A: 從零設計課程（完整流程）

適用於線上直播課、系列課程等需要完整規劃的場景。

```
0. 合作對齊（必做）
   ├── Cab 講想像（這週要什麼感覺、核心觀念是什麼）
   ├── 我問問題確認
   └── 對齊後才進入下一步

1. 素材盤點（有既有素材時）
   ├── 讀 02_素材對照.md 確認有哪些素材
   ├── 完整讀過對應素材（講座、簡報、逐字稿等）
   ├── 抽出核心觀念、金句、比喻、案例
   └── 素材是血肉，課綱是骨架

2. 錨定資訊
   ├── 定義目標受眾 Persona（背景、能力、痛點）
   ├── 明確課程承諾（銷售頁/宣傳內容說了什麼）
   ├── 建立執行原則（比例配置、高價值定義）
   └── 輸出：00_執行原則.md

3. 每週/每堂目標錨定
   ├── 銷售頁承諾對照
   ├── 本週目標（3-5 個）
   ├── 解決的痛點對照表
   ├── 具體價值產出（學員帶走什麼）
   └── 輸出：00_目標與痛點.md

4. 課綱設計
   ├── 時間分配表（段落 / 主題 / 時間 / 類型）
   ├── 各段落詳細內容
   ├── 標記【觀念】【示範】【互動】
   ├── 附件清單
   └── 輸出：01_課綱.md

5. 課程內容展開
   ├── **維持課綱段落數，不自己加段落**
   ├── 新元素融入既有段落，不獨立開段
   ├── 基於素材觀念展開，不自己發明框架
   └── 輸出：02_課程內容.md

6. 驗收檢查
   └── 參考 references/checklist.md
```

### Mode B: 單堂講座設計

```
1. 定義核心訊息 → 學員離開時要記住什麼？（不超過 3 點）
2. 設計三層結構 → 觀念層 → 方法層 → 實作層
3. 規劃情緒曲線 → HOOK(期待) → 震撼 → 驗證 → 實用 → 安心
4. 設定時間分配 → 參考 references/cognitive.md
5. 設計記憶點 → 金句、開場結尾呼應、核心概念重複
6. 驗收檢查 → 參考 references/checklist.md
```

### Mode C: 審查現有課程

```
1. 閱讀完整內容
2. 評估五維度（結構邏輯、認知負荷、情緒曲線、互動設計、記憶點）
3. 對照銷售頁承諾 → 是否兌現？
4. 識別問題與建議
5. 輸出評估報告（使用下方格式）
```

**評估報告格式**：
```markdown
## 課程設計評估

| 維度 | 評分 | 說明 |
|------|------|------|
| 結構邏輯 | ⭐⭐⭐⭐⭐ | [說明] |
| 認知負荷 | ⭐⭐⭐⭐ | [說明] |
| 情緒曲線 | ⭐⭐⭐⭐⭐ | [說明] |
| 互動設計 | ⭐⭐⭐ | [說明] |
| 記憶點 | ⭐⭐⭐⭐⭐ | [說明] |
| 承諾兌現 | ⭐⭐⭐⭐ | [說明] |

### ✅ 做得好的地方
### ⚠️ 潛在風險與建議
### 🎯 總結評價
```

## 內容比例配置

### 線上直播課標準配置

| 類型 | 比例 | 說明 |
|------|------|------|
| 觀念講解 | 20% | 為什麼需要、心智模型建立 |
| 實作示範 | 50% | 講師操作給學員看（非 workshop） |
| 整合串接 | 30% | 把片段連成完整流程 |

### 實作示範定義

- 講師操作、學員觀看（影片/截圖/步驟說明）
- 不是 workshop 讓學員自己動手
- 目標：學員看完知道怎麼做，回去能自己複製

### 高價值定義

- 學員可以**立即使用**
- 有**具體的產出物**（checklist、模板、框架）
- 解決**實際問題**，不是「知道了但不知道怎麼用」

## 三層級結構框架

適用於 60-120 分鐘的知識型講座：

| Level | 名稱 | 核心問題 | 佔比 |
|-------|------|----------|------|
| 1 | 觀念層 | 為什麼需要？ | 25-30% |
| 2 | 方法層 | 怎麼做？ | 30-35% |
| 3 | 實作層 | 用在哪？ | 20-25% |

**加上 HOOK + Close**：
```
HOOK (5-10%) → Level 1 → [驗證案例] → Level 2 → Level 3 → Close (5-10%)
```

詳細原則見 [references/structure.md](references/structure.md)

## 時間分配速查

| 講座長度 | HOOK | 主體 | Close | 單一階段上限 |
|----------|------|------|-------|-------------|
| 60 分鐘 | 3-5 min | 50 min | 5-7 min | 15 min |
| 90 分鐘 | 5-8 min | 75 min | 7-10 min | 25 min |
| 120 分鐘 | 8-10 min | 100 min | 10-12 min | 30 min |

**互動點分布**：每 20-25 分鐘至少一個互動

詳細原則見 [references/cognitive.md](references/cognitive.md)

## 情緒曲線設計

**理想曲線**：
```
期待 → 震撼 → 驗證 → 實用 → 想像 → 安心
HOOK   L1     案例    L2     L3    Close
```

**關鍵原則**：
- 首因效應：開場 30 秒決定聽不聽
- 近因效應：結尾決定帶走什麼
- 情緒錨點：用震撼例子創造記憶點

詳細原則見 [references/emotional.md](references/emotional.md)

## 觀念處理技巧

對於技術概念（前端/後端/資料庫等），使用比喻快速帶過：
- 前端 = 店面裝潢（客人看到的）
- 後端 = 廚房（處理邏輯的地方）
- 資料庫 = 倉庫（存東西的地方）
- API = 傳菜口（前後溝通的窗口）

**重點不是「理解技術」，而是「知道自己在做什麼」**

概念講完後馬上接實際工具：「所以你用 XX 的時候，它幫你處理的是哪一塊」

## 品質檢查標準

每堂課完成後檢查：

- [ ] 是否對齊銷售頁承諾？
- [ ] 是否解決對應痛點？
- [ ] 學員帶走什麼具體產出？
- [ ] 時間夠用嗎？
- [ ] 觀念/示範/整合比例是否合理？
- [ ] 標記了哪些是示範、哪些是觀念嗎？

## 首堂課 / 系列開場設計

> ⚠️ 首堂課決定學員是否「來對了」、是否會持續參與、課後社群是否活躍

### 首堂課必做清單

| 項目 | 目的 | 做法 |
|------|------|------|
| **講師自我介紹** | 建立權威 + 親近感 | 一句話定位 + 相關經歷 + 與學員的共同點 |
| **學員破冰** | 讓學員認識彼此 | 聊天室快速自介：「名字 + 想做什麼」 |
| **課程規則說明** | 降低焦慮、建立預期 | 如何發問、社群怎麼用、錄影回放時間 |
| **今天的承諾** | 讓學員知道「會帶走什麼」 | 具體列出 3-5 個產出 |
| **下週預告** | 製造期待、降低流失 | 預告具體內容 + 彩蛋 |
| **課後第一件事** | 啟動社群互動 | 一個簡單動作（例：LINE 群打「我在」） |

### 講師自我介紹模板

```markdown
<!-- 填空引導：
- 你是誰？（一句話定位）
- 為什麼是你教這堂課？（經歷/成果/資格）
- 你跟學員的共同點是什麼？（建立親近感）
-->

> 「___[一句話自我介紹]___」

**我的背景**：
- ___[相關經歷 1]___
- ___[相關經歷 2]___
- ___[為什麼我有資格教這個]___

**我跟你們一樣**：
> 「___[建立共同點]___」
```

### 作業設計原則（促進社群互動）

| 原則 | 做法 |
|------|------|
| **提供分享模板** | 統一格式讓分享更容易、更整齊 |
| **設計互動任務** | 「去看兩位同學的作業，給 👍 + 一句回饋」 |
| **分級設計** | 基礎版（必做）+ 挑戰版（選做），照顧不同程度 |
| **降低門檻** | 讓最弱的學員也能完成基礎版 |

**作業分享模板範例**：
```
【Week X 作業】
🎯 我做的是：___（一句話描述）
🔗 網址/成果：___
💡 最卡的地方：___
❓ 想問的問題：___
```

### 下週預告設計

- **具體化**：不是「下週講 XX」，而是「下週你會學到 1. ... 2. ... 3. ...」
- **彩蛋**：預告一個額外的吸引點（「我會分享我自己在用的 X 個模板」）
- **製造期待**：讓學員等不及下週

### 課後社群啟動

| 時機 | 動作 |
|------|------|
| 課程結束時 | 請學員到 LINE 群打「我在」 |
| 課後 1 小時內 | 講師在群組拋一個問題或話題 |
| 作業截止前 | 提醒 + 鼓勵先交的學員 |
| 有人交作業時 | 講師回覆 + 點名其他學員去看 |

## 何時更新這份 Skill

> **AI 主動更新規則**：以下情境發生時，AI 應主動提議更新，不需等使用者要求。

| 情境 | 更新什麼 | 操作 |
|------|----------|------|
| 完成一次課程設計 | `references/cases.md` | 將設計決策與經驗追加為案例 |
| 發現新的設計技巧 | 對應 references 檔案 | 追加技巧與範例 |
| 認知負荷/情緒曲線有新發現 | 對應 references 檔案 | 更新理論基礎 |
| 驗收檢查清單需補充 | `references/checklist.md` | 新增檢查項目 |
| 核心原則或框架需修正 | SKILL.md 對應章節 | 調整原則或框架 |

### 更新原則

1. **實證驅動**：只收錄經過實際講座驗證的洞察
2. **保留脈絡**：更新時標注「何時、因哪場講座發現」
3. **精簡為上**：SKILL.md 放原則，細節放 references/
