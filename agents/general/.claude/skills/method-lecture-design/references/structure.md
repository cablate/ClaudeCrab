# 結構設計原則

## 三層級結構詳解

### Level 1: 觀念層（Why）

**目的**：建立認知基礎，回答「為什麼需要」

**設計原則**：
- 從痛點出發，不是從解決方案出發
- 用對比製造認知衝突（舊觀念 vs 新觀念）
- 用震撼例子強化記憶

**常見錯誤**：
- ❌ 直接講功能，沒有建立動機
- ❌ 假設學員已經知道為什麼需要
- ❌ 用太多專業術語

**範例結構**：
```
1. 痛點描述（學員共鳴）
2. 舊觀念的問題（認知衝突）
3. 新觀念介紹（認知轉變）
4. 震撼例子（記憶錨點）
5. 金句總結
```

---

### Level 2: 方法層（How）

**目的**：提供可執行的方法論

**設計原則**：
- 用已知框架包裝新知識（降低學習門檻）
- 每個方法都要有具體範例
- 區分「原則」和「規則」——教原則

**常見錯誤**：
- ❌ 只講理論沒有範例
- ❌ 步驟太多記不住（超過 5 步就要拆分）
- ❌ 沒有說明「為什麼這樣做」

**範例結構**：
```
1. 方法論總覽（一張圖/一句話）
2. 步驟 1 + 範例
3. 步驟 2 + 範例
4. ...
5. 常見錯誤 + 如何避免
6. 小結
```

---

### Level 3: 實作層（Where）

**目的**：連結到學員自己的情境

**設計原則**：
- 提供多種應用方向（擴展想像）
- 讓學員思考自己的應用（互動）
- 給出具體的下一步行動

**常見錯誤**：
- ❌ 應用方向太抽象
- ❌ 沒有互動，學員只是聽
- ❌ 沒有具體的下一步

**範例結構**：
```
1. 應用方向總覽
2. 方向 1 + 一句話說明
3. 方向 2 + 一句話說明
4. 互動：想想你的應用
5. 下一步行動（具體、可執行）
```

---

## HOOK 設計原則

**目的**：抓住注意力、建立期待、預告差異化

**定位原則**：HOOK 的職責是建立慾望與期待，不是解釋機制。如果某個概念在後面章節會完整展開，HOOK 只需點到為止——讓聽眾「意識到這件事存在」就夠了，不要在 HOOK 裡展開說明。

> 💡 來源：AgentSkill 講座 HOOK 優化（2026-02）。原版在 HOOK 放了「官方背書 Domain Expertise」的機制解釋，但這在 Framework 章節才完整展開，導致 HOOK 過長且搶了後面的驚喜感。

**核心元素**（依序，可選標記 ⚡ 為必要、💡 為可選）：

1. ⚡ **痛點共鳴**：「你有沒有遇過...」
2. ⚡ **願景描繪**：「想像如果...」
3. ⚡ **差異化宣示**：「我不是要教你 X，我是要教你 Y」
4. ⚡ **結構預告**：「今天我們會...」
5. 💡 **開課/演講動機**：「我為什麼要講這個」（建立真實感與權威感，適合放在最前面）
6. 💡 **反 FOMO 預告**：「學完今天的內容，你就夠用了」（與 Close 的反 FOMO 收尾形成閉環）
7. 💡 **定位收尾**：「別人還在 X，我們已經 Y」（製造領先感，適合作為 HOOK 最後一句）

**時間分配**：
- 開課動機（可選）：30 秒
- 痛點共鳴：30-60 秒
- 願景描繪：30-60 秒
- 差異化宣示：30-60 秒
- 反 FOMO 預告（可選）：30 秒
- 結構預告：30-60 秒
- 定位收尾（可選）：20 秒

**段落間銜接常見陷阱**：

| 陷阱 | 說明 | 修正方式 |
|------|------|----------|
| **強制因果連結** | A 段講了 X，B 段要講 Y，硬寫「X 導致 Y」來連接，但 X 和 Y 其實沒因果關係 | 用話題轉換即可（「那在開始之前…」「好，接下來…」），不需要假裝有邏輯關係 |
| **承諾-兌現落差** | 用升級語（「不只是 X 而已」「X 只是開始」）但接下來其實還是同一件事的正面版本 | 升級語只在真的要升級時用；同層展開用平行語氣（「那如果有一個方法，可以一次解決呢？」） |

> 💡 來源：AgentSkill 講座 HOOK 優化（2026-02）。
> - 強制因果：原版用「那大家理解的問題，會造成什麼困擾呢？」把「誤解 Skill」和「重複教 AI」硬連因果，實際是兩個獨立議題。
> - 承諾落差：原版用「但 Skill 要解決的，不只是『不用重新教』而已」，但願景段落本質上還是「不用重新教」的正面版。

**金句句式參考**：
- 差異化宣示：「別人教你 X，我教你 Y」
- 價值重定義：「這不是 A，是 B」
- 反焦慮：「學完今天的內容，你就夠用了」
- 領先感：「別人還在 X，我們已經在 Y 了」

## 內容超時處理原則

**問題**：某個階段試講後發現超時。

**處理優先順序**：

1. **砍掉後面會完整覆蓋的內容**：如果某段概念在後面階段會深入展開，HOOK 或前面階段只需留一句話當「麵包屑」，不需要在此展開
2. **合併相近的段落**：把功能類似的段落合併（例：反 FOMO + 收尾可以合成一段）
3. **降低展開程度**：保留核心句，刪掉解釋和舉例
4. **最後手段：刪除整段**：確認該段內容在其他階段有覆蓋後才刪

**麵包屑原則**：被砍掉的內容，保留一句話讓聽眾「意識到這件事存在」。後面階段展開時，聽眾會有「啊，前面有提到」的連結感。

## Close 設計原則

**目的**：強化記憶、消除焦慮、給出行動

**核心元素**：
1. **快速回顧**：總結核心觀念（不超過 3 點）
2. **呼應開場**：形成閉環
3. **情緒定調**：學員帶著什麼感覺離開？
4. **下一步行動**：具體、可執行、低門檻

**反 FOMO 收尾**（適用於資訊爆炸主題）：
- 核心訊息：「你已經學到最重要的東西了」
- 語氣：直接、有力量、不拖泥帶水
- 效果：學員感到「安心」而非「還有很多要追」

**範例結構**：
```
「那些 [市場上的焦慮來源]？跟你沒關係。
專注在你自己的問題上，
[用今天學到的方法] 解決它。
這就是今天最重要的收穫。」
```

## 驗證案例的定位

**目的**：用實際案例驗證觀念層的概念

**不是**：
- ❌ 深度剖析每個案例
- ❌ 獨立教方法

**而是**：
- ✅ 快速展示「真的有人這樣做」
- ✅ 驗證觀念層的概念真的有效
- ✅ 讓學員產生「原來是這樣用」的感覺

**範例結構**：
```
案例 1：驗證概念 A（3-5 分鐘）
案例 2：驗證概念 B（3-5 分鐘）
案例 3：驗證概念 C（3-5 分鐘）
小結：這些不是理論，是實際做過的案例
```
