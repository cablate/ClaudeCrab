## VibeCoding 線上課（2026-02）

**背景**：4 週線上直播課，每週 2 小時，受眾為設計師/PM/行銷，目標是 4 週內做出可收費產品

### 系列課程設計模式

**課綱結構模板**：
```
開場（5min）→ 觀念建立（15-20min）→ 示範（25-30min）
→ 休息（5min）→ 示範/模板（20min）→ 進階（15min）
→ 整合收斂（10min）→ 總結+Q&A（10min）
```

**每段落必備格式**：
- 目標：這段要達成什麼
- 內容：具體講什麼（含時間分配）
- 學員帶走：這段結束學員得到什麼

**附件清單設計**：
- 每堂課結尾列出「本週學員帶走的具體產出」
- 格式：checkbox list，讓學員可以自己核對
- 產出物類型：模板、checklist、框架、SOP、速查卡

**品質檢查標準**：
- [ ] 對齊銷售頁承諾？
- [ ] 解決對應痛點？
- [ ] 有具體產出物？
- [ ] 2 小時時間夠用？
- [ ] 觀念/示範/整合比例合理？
- [ ] 標記了示範 vs 觀念？

### Week 2 Skill 設計 踩坑記錄（血淚教訓）

**問題 1：課程內容必須 sync 課綱，不要自己加段落**
- 初版問題：課綱 9 段，我改成 11 段（自己加了案例驗證、漸進式揭露獨立段）
- 後果：課綱和內容脫鉤，架構混亂
- 正確做法：維持課綱段落數，把新元素融入既有段落而非新增段落

**問題 2：機制要融入，不是獨立講**
- 漸進式揭露機制 → 融入段落 2「為什麼需要 Skill」
- 協作者心態 → 融入段落 4「現場設計」
- 不要為了每個觀念都開獨立段，會把節奏拖慢

**問題 3：沒讀素材就展開**
- 我用通用「角色+任務+約束+格式」公式，沒讀 AgentSkill 講座素材
- 結果漏了核心觀念：「給原則不給規則」「AI 是協作者」「設計思維五階段」
- 正確做法：先讀 `02_素材對照.md`，讀完整素材，再展開

**問題 4：課綱已經有好的節奏，不要亂改**
- 課綱節奏：痛點 → 本質 → 公式 → 現場設計
- 這個節奏直接、快速，學員不會等太久才看到怎麼做
- 我的版本繞太遠：哲學 → 案例 → 機制 → 公式 → 設計

**Week 2 最終架構決策**：
- 段 2：痛點 → Skill 本質 → 漸進式揭露 → 範例展示
- 段 3：frontmatter 格式 + 入門公式
- 段 4：協作者心態 + 設計思維五階段 + 現場設計
- 段 6：模板都加核心原則

### Week 1 開發架構 設計決策

**比例配置**：
- 觀念 20% / 示範 50% / 整合 30%
- 原因：受眾是非工程師，需要大量「看著做」而非純聽講

**技術概念處理**：
- 決策：用餐廳比喻（前端=店面、後端=廚房、資料庫=倉庫、API=傳菜口）
- 原因：受眾不需要「理解」技術，只需要「知道自己在做什麼」

**工具選擇段落**：
- 決策：先比較 4 個工具，再給出推薦路徑（Lovable → Cursor）
- 原因：解決「工具選擇焦慮」這個痛點，讓學員不再糾結

### 可複用洞察

1. **概念講完馬上接工具**：「所以你用 XX 的時候，它幫你處理的是哪一塊」——這個銜接句很有效
2. **比喻要能跨段落使用**：餐廳比喻在後續講部署、API 時都能繼續延伸
3. **工具比較不是列功能，是解決焦慮**：重點是「你應該用哪個」而非「每個有什麼」

## AgentSkill 講座（2026-02）

**背景**：90 分鐘單場講座，受眾為 AI 使用者，主題是 Claude Agent Skill 設計

### HOOK 優化決策

**問題**：原版 HOOK 超時（紙面 5 分鐘，試講 8 分鐘）

**處理方式**：
1. 砍掉「官方背書 Domain Expertise」機制解釋（後面 Framework 會展開）
2. 合併「反 FOMO 預告」和「結構預告」
3. 移除強制因果連結

**踩坑**：
- 「誤解 Skill」和「重複教 AI」是兩個獨立議題，但原版硬用因果連結
- 修正：改用話題轉換（「那在開始之前…」）

### 可複用洞察

1. **HOOK 只建立慾望，不解釋機制**：機制放後面章節，HOOK 留麵包屑就好
2. **升級語要謹慎**：「不只是 X 而已」後面必須真的升級，否則用平行語氣
3. **紙面時間 ×1.5-2 = 實際時間**：設計完一定要試講計時
