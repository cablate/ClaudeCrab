# 欄位完整規格

## 必填欄位

### content_id (string, required)
待分析內容的 UUID。

### content_type (string, required)
8 種預定義值之一：

| 值 | 判斷標準 |
|---|---|
| `知識教學` | 讀者讀完會「學到東西」— 解釋概念、教方法、給步驟 |
| `經驗分享` | 有「我做了 X，結果 Y」的敘事 — 分享親身經歷與結果 |
| `觀點表達` | 有明確的個人觀點或主張 — 表達立場、判斷、預測 |
| `資源整理` | 主體是「列舉 + 簡評」— 推薦工具、書單、資源列表 |
| `問題探討` | 重點在「問」而非「答」— 提出問題、分析困境 |
| `靈感筆記` | 短、發散、沒有完整論述 — 碎片想法、未成形的洞察 |
| `經營紀錄` | 有具體數字或里程碑 — 數據回顧、成長紀錄 |
| `日常互動` | 主要功能是「維持存在感」— 閒聊、回應時事、社交 |

### topics (array, required)
可以是空陣列 `[]`。每個元素包含：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `topic` | string | 主題名稱 |
| `confidence` | `"core"` \| `"related"` \| `"peripheral"` | 關聯程度 |

> `weight` 已廢除（2026-02-28），傳入時靜默忽略。

一篇內容通常標 1-4 個 topics。

### key_insights (string[], required)
1-3 條可獨立成立的核心觀點。純日常互動可以是空陣列 `[]`。

- 用陳述句，不用疑問句
- 脫離原文仍有意義
- 寧少勿濫

### knowledge_density (number, required)
整數 1-10，衡量知識資產化潛力。

五個維度（每項 +2）：明確觀點、可操作方法、具體經驗佐證、深入分析、原創性。

### density_reasoning (string, required)
必須包含所有五個維度的判定，即使得 0 分也要寫。每維度只有 +0 或 +2（不存在 +1）。

正確格式：
`"有明確觀點(+2)、有可操作方法(+2)、缺具體經驗佐證(+0)、有深入分析(+2)、觀點具原創性(+2) = 8"`

錯誤範例：
- ❌ `"趣味展示，無知識內容"` — 未逐維度說明
- ❌ `"有觀點(+1)、太短未展開(+1)"` — +1 不存在

### analyzed_by (string, required)
執行分析的模型名稱，例如：
- `"claude-opus-4-6"`
- `"claude-sonnet-4-20250514"`
- `"gpt-4o"`

## 本階段暫不需填的欄位

以下欄位不需要傳入，API 會自動使用預設值。Phase 4 聚合分析階段再處理。

| 欄位 | 預設值 | 說明 |
|---|---|---|
| `layer_positions` | [] | 知識層定位 |
| `supports_principles` | [] | 支撐的核心理念 |
| `action` | null | 後續處理建議 |
| `action_note` | "" | 處理建議說明 |
