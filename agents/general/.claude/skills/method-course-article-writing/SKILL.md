# 課程文章寫作方法

## 觸發情境

當需要為「已有主線課程」撰寫以下內容時觸發：
- DLC / 補充章節（如新增支付方式整合教學）
- 進階主題延伸（假設讀者已完成基礎課程）
- 替代方案說明（如 A 服務 vs B 服務的差異）

**不適用**：
- 主線課程的核心章節（那需要從零教起）
- 獨立的技術文章（不預設讀者有特定前置知識）
- 講座講義或 Workshop 教材（互動性質不同）

---

## 核心原則

### 1. DLC 不是主線的複製

**反模式**：把主線教過的概念重新講一遍
**正確做法**：明確說「這跟你學過的 X 有 Y% 相似，差別只在 Z」

**實例**：
- ❌ 「支付流程分為：建立訂單 → 導向支付頁 → Webhook 確認...」（主線教過了）
- ✅ 「八成一樣，CheckMacValue 用途？防竄改。Webhook 重要性？唯一可信來源。那差在哪？」

### 2. 減焦慮，再聚焦差異

**人性**：看到「新的整合」會擔心「又要重新學一套」
**開場策略**：先降焦慮（告訴他們大部分是一樣的），再講差異點

**結構模板**：
```
## 先說結論：流程沒變
[用一句話解釋核心概念 = 你已經學過的]

## 那到底差在哪？
### 差異 1: [具體、可操作的差異點]
### 差異 2: ...
```

### 3. 用決策樹，不是流程圖

**為什麼**：DLC 讀者已經懂流程，他們需要的是「這個情境該選什麼」

**範例**：
- ❌ 流程圖：「步驟 1 → 步驟 2 → 步驟 3」（主線教過了）
- ✅ 決策樹：「數位商品？→ Print=0, CarrierType=1（只需 Email）」

### 4. 保持課程整體風格

**方法**：寫之前先讀主線課程 2-3 章，提取：
- **語調**：是技術文件風格？還是朋友聊天風格？
- **Metaphor**：用什麼日常比喻（如「會計邏輯」「鬧鐘機制」）
- **技術深度**：給完整 code？還是點到為止？

**紅線**：如果讀者讀 DLC 時覺得「這不像同一個老師寫的」= 失敗

### 5. 點到為止，不重複教學

**判斷標準**：主線課程教過的概念，DLC 只需要「提醒 + 指出差異」

**實例**：
- 主線教過「Webhook 是唯一可信的狀態來源」
- DLC 不需要重新解釋為什麼，只需說「這點跟 PAYUNi 一樣」

## 工作流程

### Phase 1: 需求分析

使用 **5 問確認法**（詳見 `references/requirement-checklist.md`）：
1. 融合 vs 獨立？（是主線的延續，還是獨立成章？）
2. 目標受眾？（預設讀者已有什麼程度的前置知識？）
3. 交付格式？（純文章？影片腳本？簡報？）
4. 內容拆分？（一篇搞定，還是拆成多篇？）
5. 技術深度？（給完整 code？還是點到為止？）

**目的**：避免「我以為你要 A，結果你要 B」的來回修改

### Phase 2: 風格對齊

**步驟**：
1. 讀主線課程 2-3 章（特別是「前言」和「核心章節」）
2. 提取風格特徵（詳見 `references/style-alignment.md`）：
   - 語調（technical vs conversational）
   - Metaphor 使用方式
   - 段落結構（是否有預告下章？）
   - 技術深度範例
3. 記錄「這門課的獨特風格是什麼」

### Phase 3: 架構設計

**使用工具包**（詳見 `references/structure-toolkit.md`）：
- 減焦慮開頭（「八成一樣，差在哪？」模式）
- 差異點聚焦（用「差異 1、2、3」而非「步驟 1、2、3」）
- 決策樹 > 流程圖
- 插圖標註位置（什麼地方需要視覺輔助？）
- 預告下章（保持課程連貫性）

### Phase 4: 初稿撰寫

**核心檢查**：
- [ ] 開頭有沒有降焦慮？
- [ ] 有沒有重複教主線教過的東西？
- [ ] 差異點是否清晰、可操作？
- [ ] 語調是否符合主線風格？
- [ ] 有沒有標註插圖位置？

### Phase 5: 品質把關

**三條紅線**（詳見 `references/quality-standards.md`）：
1. **太技術**：code 太多、術語沒解釋、讀起來像 API 文件
2. **太水**：沒有實質差異點、只是換個說法重複主線
3. **人設崩壞**：語調、metaphor、結構跟主線差太多

**修正方向判斷樹**：
- 收到「太跳」→ 可能是太技術，或風格不一致
- 收到「太水」→ 可能是重複教學，沒聚焦差異
- 收到「不像同一門課」→ 風格對齊失敗

## 成功標準

一篇合格的課程 DLC 文章應該：
1. **讀者不焦慮**：知道大部分是熟悉的，只需關注差異
2. **差異點清晰**：看完知道「這次要注意什麼不一樣」
3. **風格一致**：感覺像同一個老師寫的
4. **不重複教學**：主線教過的不再贅述
5. **可操作**：讀完能實際應用（不是純理論）

## 主動更新時機

- 完成新的課程 DLC 後，記錄新的架構模式到 `references/structure-toolkit.md`
- 發現新的「太技術/太水/人設崩壞」案例時，更新 `references/quality-standards.md`
- 5 問確認法需要調整時，更新 `references/requirement-checklist.md`
- 累積到 3+ 個案例時，在 `examples/` 中新增案例文件
