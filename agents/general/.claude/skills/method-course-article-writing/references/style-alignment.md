# 風格對齊方法

## 為什麼需要風格對齊

**問題**：DLC 文章跟主線課程風格差太多 → 讀者感覺「不像同一個老師寫的」→ 信任感下降

**目標**：讓讀者無縫接軌，感覺 DLC 就是主線的自然延伸

---

## 風格的四個維度

### 1. 語調 (Tone)

**光譜**：
```
技術文件風格 ←→ 朋友聊天風格
(formal)         (conversational)
```

**如何判斷**：
- 讀主線 2-3 章，記錄：
  - 使用「你/我」還是「用戶/開發者」？
  - 有沒有口語化表達（「欸」「對吧」「其實」）？
  - 句子長度（短句 vs 長句）？

**ECPay DLC 案例**：
- 主線語調：朋友聊天風格（「你會遇到」「其實很簡單」）
- DLC 對齊：「八成一樣，差在哪？」「欸，這個要注意」

---

### 2. Metaphor（比喻使用方式）

**為什麼重要**：好的課程會建立一套「專屬比喻系統」，讓抽象概念變具體

**如何提取**：
- 主線課程用了什麼日常比喻？
  - 例：「會計邏輯」（父單子單）
  - 例：「鬧鐘機制」（訂閱制自動扣款）
- 比喻的風格是什麼？
  - 生活化？商業場景？技術類比？

**ECPay DLC 案例**：
- 主線比喻風格：日常生活 + 商業場景
- DLC 對齊：沒有硬塞比喻（因為講的是技術差異，不是抽象概念）

**紅線**：
- ❌ 主線都用生活比喻，DLC 突然用技術類比
- ❌ 主線沒用比喻，DLC 突然冒出一堆比喻

---

### 3. 段落結構

**檢查項目**：
- **開頭**：是直接進主題？還是先給背景/動機？
- **小結**：每個段落結束有沒有一句話總結？
- **預告**：章節結尾有沒有預告下一章？
- **節奏**：長段落 vs 短段落？

**ECPay DLC 案例**：
- 主線結構：先背景 → 核心概念 → 實作 → 預告下章
- DLC 對齊：
  ```
  ## 先說結論（降焦慮）
  ## 差異點 1, 2, 3（核心內容）
  ## 下一篇預告（保持連貫）
  ```

---

### 4. 技術深度

**光譜**：
```
給完整 code ←→ 只講概念
(implementation)  (conceptual)
```

**如何判斷**：
- 主線課程的 code snippet 長度？
- 有沒有逐行解釋 code？
- 還是只給關鍵參數 + 概念說明？

**ECPay DLC 案例**：
- 主線深度：給關鍵 code + 概念解釋（不是完整 copy-paste）
- DLC 對齊：
  ```javascript
  // ✅ 只給關鍵差異
  const params = { ItemName: "Apple iPhone" }  // ❌ 空格會變 Apple%20iPhone
  
  // ❌ 不給完整實作（主線已經教過了）
  ```

---

## 實戰流程

### Step 1: 選擇參考章節

**建議讀**：
- **前言**（建立課程整體語調）
- **核心章節 1-2 章**（看技術內容怎麼講）
- **如果有其他 DLC**（看 DLC 風格是否與主線一致）

### Step 2: 填寫風格特徵表

| 維度 | 主線特徵 | DLC 如何對齊 |
|------|---------|-------------|
| 語調 | (e.g., 朋友聊天風格) | 保持口語化、用「你/我」 |
| Metaphor | (e.g., 會計邏輯、鬧鐘機制) | 必要時沿用，不硬塞新比喻 |
| 段落結構 | (e.g., 背景→概念→實作→預告) | 遵循相同結構 |
| 技術深度 | (e.g., 關鍵 code + 概念) | 只給差異點的 code |

### Step 3: 寫一段測試

**方法**：寫一小段（100-200 字），拿去跟主線課程對比

**檢查**：
- 如果這段插進主線課程裡，讀者會覺得突兀嗎？
- 語調、節奏、metaphor 是否一致？

---

## 常見錯誤

### 錯誤 1: 過度模仿表面形式

❌ 主線每段都有比喻 → DLC 也硬塞比喻
✅ 理解「為什麼用比喻」→ 只在需要時用

### 錯誤 2: 忽略技術深度差異

❌ 主線都點到為止 → DLC 突然給一大段 code
✅ 保持相同的技術深度光譜位置

### 錯誤 3: 只看一章就下結論

❌ 只讀前言 → 誤以為整門課都是「激勵型」語調
✅ 至少讀 2-3 章（包括技術章節）才能確定風格

## ECPay DLC 風格對齊案例

### 主線課程風格分析

**語調**：
- 朋友聊天（「你會遇到」「其實」「對吧」）
- 第二人稱（你/我）

**Metaphor**：
- 會計邏輯（父單子單）
- 鬧鐘機制（訂閱制）
- Silicon Valley Dark Mode（前言簡報風格）

**段落結構**：
- 開頭給動機/背景
- 核心概念用日常語言解釋
- 實作部分點到為止
- 章節結尾預告下章

**技術深度**：
- 給關鍵參數 + 概念
- 不給完整 copy-paste code

### DLC 如何對齊

**v1（失敗案例）**：
- ❌ 太多 code snippet
- ❌ 直接講技術細節，沒有降焦慮開頭
- ❌ 語調變成「技術文件風格」

**v2（成功案例）**：
- ✅ 開頭「八成一樣，差在哪？」（降焦慮 + 朋友語調）
- ✅ 只給差異點的 code（技術深度一致）
- ✅ 保持「你/我」第二人稱
- ✅ 章節結尾預告下篇（結構一致）
