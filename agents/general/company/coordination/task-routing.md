# 任務路由 SOP

**使用者**：秘書
**目的**：收到任務後，快速判斷該分給誰、怎麼分

---

## 路由決策樹

```
收到任務
  ├── 寫文字內容？→ Writer
  │     └── 是社群貼文？→ Writer（附 social-post-optimizer context）
  │     └── 是課程 DLC？→ Writer（附 method-course-article-writing context）
  ├── 做視覺/影片？→ Media
  │     └── 需要文字腳本？→ 先 Writer 再 Media
  ├── 寫程式/修 bug？→ Coder
  │     └── 是開源專案？→ OSS-Coder
  ├── 轉錄/萃取知識？→ Transcriber
  ├── SEO 相關？→ SEO
  ├── 客戶準備/跟進？→ 業務助理
  ├── 市場調研/趨勢？→ Researcher
  ├── 排程/數據/行政？→ Operator
  ├── Agent 配置/系統？→ Admin
  └── 不確定？→ 秘書自行處理或先診斷再分派
```

---

## 分派前檢查

1. **任務明確嗎？**
   - 模糊 → 先跟 Cab 確認範圍再分派
   - 明確 → 直接分派

2. **有足夠 context 嗎？**
   - 不夠 → 補充 context 再分派（不要讓下游自己猜）
   - 夠 → 直接分派

3. **跨角色嗎？**
   - 單一角色 → 直接分派
   - 跨角色 → 拆分成子任務，分別分派，標明依賴關係

4. **有優先順序衝突嗎？**
   - 有 → 判斷哪個更緊急/重要，或跟 Cab 確認
   - 沒有 → 直接分派

## 常見錯誤

| 錯誤 | 後果 | 正確做法 |
|------|------|---------|
| 任務分給錯的人 | 來回 bounce、浪費時間 | 用決策樹判斷 |
| Context 不夠 | 對方做錯方向 | 補充背景再分派 |
| 沒拆跨角色任務 | 卡在某一環 | 拆分 + 標依賴 |
| 所有事都自己做 | 瓶頸、品質下降 | 能分就分 |

## 路由準確率追蹤

每月回顧：
- 任務 bounce 次數（分派後被退回重新分派）
- 目標：bounce rate ≤ 10%
