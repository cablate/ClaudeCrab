# SOP 05：企業內訓提案

**版本**：v1.0
**建立日期**：2026-03-17
**最後更新**：2026-03-17

---

## 觸發條件

B 端諮詢後，客戶明確表示有企業內訓需求（包含：內部培訓、員工 AI 能力提升、客製化工作坊等形式）。

---

## 流程圖

```
[客戶提出內訓需求]
        ↓
[業務助理] 整理需求規格書（2 天）
        ↓
[Researcher] 蒐集產業 AI 應用案例（3 天）
        ↓
[秘書] 設計內訓架構（2 天）
        ↓
[業務助理] 撰寫提案書初稿
        ↓
[秘書] 品管審核
        ↓
[Cab] 最終審核 + 報價確認
        ↓
[業務助理] 發送提案 + 追蹤回覆
        ↓
  ┌─── 未成案 ───┐     ┌─── 成案 ───┐
  ↓              ↓     ↓            ↓
[歸檔]     [修訂提案] [Cab 教學交付] [Media/Coder 準備]
                              ↓
                    [業務助理] 課後回饋收集 + 後續服務推薦
```

---

## 詳細步驟

### Step 1：需求整理

| 項目 | 內容 |
|------|------|
| **負責人** | 業務助理 |
| **輸入** | B 端諮詢紀錄、客戶訊息 |
| **動作** | 與客戶確認五要素：人數、程度（AI 基礎/進階）、學習目標、課時需求、預算範圍 |
| **輸出** | 需求規格書（標準格式，含五要素） |
| **品質檢查點** | 五要素齊全（人數/程度/目標/時數/預算），缺任何一項不得進入下一步 |
| **時限** | 客戶確認需求後 2 天 |

### Step 2：產業案例蒐集

| 項目 | 內容 |
|------|------|
| **負責人** | Researcher |
| **輸入** | 需求規格書（客戶產業、目標） |
| **動作** | 蒐集 3-5 個與客戶產業相關的 AI 應用案例，含來源連結、應用場景、成效數據 |
| **輸出** | 產業案例包（結構化文件，每個案例：背景 + 做法 + 成效 + 來源） |
| **品質檢查點** | 案例與客戶產業高度相關（不能用通用案例充數）；全部附有可驗證來源 |
| **時限** | 需求確認後 3 天 |

### Step 3：內訓架構設計

| 項目 | 內容 |
|------|------|
| **負責人** | 秘書 |
| **輸入** | 需求規格書 + 產業案例包 |
| **動作** | 設計課程架構：主題模組、課綱大綱、實作環節規劃、時間分配表 |
| **輸出** | 課程架構文件（主題 + 課綱 + 實作環節 + 時間分配） |
| **品質檢查點** | 架構對齊客戶學習目標；實作環節可在指定時數內完成；難度符合客戶程度 |
| **時限** | 收到需求規格書 + 產業案例包後 2 天 |

### Step 4：提案書撰寫

| 項目 | 內容 |
|------|------|
| **負責人** | 業務助理 |
| **輸入** | 課程架構文件 + 產業案例包 |
| **動作** | 撰寫完整提案書：背景分析、課程規劃、預期成果、報價方案 |
| **輸出** | 提案書初稿（PDF 格式） |
| **品質檢查點** | 專業性（無錯字、格式整齊）；對齊客戶需求（背景分析準確）；報價合理（對齊市場行情） |
| **時限** | 收到課程架構後 2 天 |

### Step 5：品管審核

| 項目 | 內容 |
|------|------|
| **負責人** | 秘書 |
| **輸入** | 提案書初稿 |
| **動作** | 審核邏輯一致性、用詞專業度、報價合理性（對照市場行情） |
| **輸出** | 審核意見（通過 / 需修改 + 具體修改點） |
| **品質檢查點** | 邏輯自洽無矛盾；用詞專業不口語；報價有依據 |
| **時限** | 收到初稿後 1 天 |

### Step 6：最終審核與報價確認

| 項目 | 內容 |
|------|------|
| **負責人** | Cab |
| **輸入** | 審核後的提案書 |
| **動作** | 確認技術內容正確、教學可執行性、最終報價簽核 |
| **輸出** | 確認版提案書（Cab 簽核） |
| **品質檢查點** | 技術內容無誤；Cab 可執行（不超過能力邊界）；報價 Cab 確認 |
| **時限** | 收到審核稿後 1 天 |

### Step 7：發送提案與追蹤

| 項目 | 內容 |
|------|------|
| **負責人** | 業務助理 |
| **輸入** | 確認版提案書 |
| **動作** | 發送提案書；追蹤回覆（發送後 3 天、1 週、2 週各追蹤一次） |
| **輸出** | 客戶回覆紀錄；成案/未成案結果 |
| **品質檢查點** | 追蹤節奏確實執行；客戶反饋完整記錄 |
| **時限** | 提案發送後 2 週內確認結果 |

### Step 8-11：成案後執行（僅成案時啟動）

| 步驟 | 負責人 | 內容 |
|------|--------|------|
| 8. 教學交付 | Cab | 現場或線上授課，依提案規格執行 |
| 9. 課程素材製作 | Media | 如需要補充視覺素材（簡報、概念圖）時啟動 |
| 10. 實作環境準備 | Coder | 如需要 Starter Kit、練習環境時啟動 |
| 11. 課後回饋 | 業務助理 | 收集滿意度問卷；推薦後續服務（進階課程、顧問、AI 系統開發） |

## 交接規範

| 交接 | 交付物 | 驗收標準 |
|------|--------|----------|
| 業務助理 → Researcher | 需求規格書 | 五要素齊全 |
| Researcher → 秘書 | 產業案例包 | 3-5 個相關案例 + 來源 |
| 秘書 → 業務助理 | 課程架構文件 | 含主題/課綱/實作/時間分配 |
| 業務助理 → 秘書 | 提案書初稿 | PDF，含四大區塊 |
| 秘書 → Cab | 審核後提案書 + 審核意見 | 邏輯清楚、意見明確 |

## 異常處理

| 情況 | 處理方式 |
|------|----------|
| 客戶預算遠低於報價（差距 > 30%） | 秘書評估是否可縮減時數或調整內容降低成本；若縮減後仍不符 Cab 的底線，誠實告知無法配合 |
| 客戶要求超出 Cab 專業範圍 | 誠實告知能力邊界；可推薦合適的其他資源或顧問，不接不可執行的案子 |
| 成案後客戶臨時變更需求 | 業務助理評估變更幅度；小幅調整（< 10% 時數）內部消化；大幅變更需重新報價並更新合約 |
| 提案書需要多次修改 | 超過 2 輪修改時，秘書與業務助理確認需求理解是否有落差，從 Step 1 重新校準 |

## 品質指標

| 指標 | 目標值 | 量測方式 |
|------|--------|----------|
| 提案書產出時間 | ≤ 1 週（從需求確認到發送） | 時間戳記追蹤 |
| 提案→成案轉化率 | 目標由 Cab 設定，初期追蹤基準值 | 每月統計 |
| 內訓後客戶推薦度 | ≥ 4.5 / 5 | 課後問卷 |
| 追蹤到位率 | 100%（三個追蹤節點全部執行） | 業務助理回報 |
