# Daily Reflection Protocol

本文件定義每日反思排程的執行協議。所有 Agent 的 `daily-reflection.yaml` 排程都應遵循此協議。

## 核心原則

- **你是合成者，不是收集者**：不重複工作中已經學到並記錄的內容
- **上網搜尋是核心步驟，不是可選步驟**：發現缺口後必須主動搜尋
- **對照使用者期待**：以 CLAUDE.md「使用者期待」區段為基準
- **使用者期待是成長方向，不是及格線**：沒有缺口也要朝期待更進一步

## 日期定義

本排程在凌晨 03:00 觸發。反思對象是**昨天**（觸發日的前一天）。
例：03:00 on 2026-03-03 觸發 → 反思對象 = 2026-03-02。

以下所有「昨天」均指反思對象日期。

## Phase 0：Memory Cleanup（記憶整理）

**每次反思的第一步，不可跳過。**

這個步驟將昨天的原始 memory/ 日誌整理成結構化格式，同時提取觀察和 pattern。整理後的乾淨日誌會被 Phase 1 使用。

**操作**：

1. 用 `list_dir` 列出 `memory/` 目錄
2. 找到昨天（及近 3 天內未整理的）日誌檔案（YYYY-MM-DD.md 格式）
3. 對每個檔案，檢查末尾是否有 `<!-- 已整理 -->` 標記
   - 有標記 = 已整理，跳過
   - 無標記 = 未整理，處理它
4. 如果全部已整理或沒有日誌 → 跳到「判斷工作日」

**對每筆未整理的日誌**：

1. **提取使用者觀察** → 追加到根目錄 `USER.md` 的 Observations 區塊
2. **辨識重複 pattern** → 升級到根目錄 `MEMORY.md` 的 Recurring Patterns 區塊
3. **清理 MEMORY.md** 過時/錯放內容
4. **日誌重整**：將流水帳轉成結構化日誌，覆蓋原檔
   - 按主題分組，不按時間排列
   - 每個主題：做了什麼 → 為什麼 → 結果/學到什麼
   - 保留互動脈絡（使用者的狀態、反應、決策原因）
   - 刪除純操作記錄（讀取檔案、執行指令）
   - 保留有未來參考價值的內容（踩坑、決策、發現）
5. **標記已整理**：在檔案末尾加上 `<!-- 已整理 -->`

**重整後格式**：
```markdown
# YYYY-MM-DD

## [主題]
- 背景：為什麼做這件事
- 過程：關鍵步驟和決策
- 結果：完成什麼、學到什麼
- 使用者狀態：（如有觀察）
```

**檔案位置提醒**：
- USER.md 和 MEMORY.md 在 agent 根目錄（與 CLAUDE.md 同層），不是 memory/ 目錄

## 判斷：昨天有沒有工作？

在開始 Phase 1 前，先判斷昨天有沒有使用者互動（依據 Phase 0 處理的日誌內容）：

- 有 → 進入**工作日模式**（Phase 1-5 完整執行）
- 沒有 → 進入**主動學習日模式**（見下方獨立區段）

## 工作日模式（五階段流程）

### Phase 1：回顧昨日記錄

**操作**：
1. 讀取 `memory/` 中昨天的日誌（Phase 0 已整理成結構化格式）
2. 掃描 CLAUDE.md Lessons Learned 區段中昨天新增的條目
3. 掃描 `knowledge/` 中昨天新增或修改的檔案

**產出**：「昨天已學清單」——已經記錄的知識和經驗

### Phase 2：對照使用者期待 + 追蹤前日缺口

**操作**：
1. 讀取 CLAUDE.md 的「使用者期待」區段
2. **提取使用者回饋信號**：從昨天的 `memory/` 日誌中找出使用者的直接回饋——修正你的產出、批評、讚賞、要求重做、直接改掉你寫的東西。這些是最直接的品質信號，不能遺漏。
3. 逐條對照昨天的工作表現（結合使用者回饋信號）
4. 識別：哪些期待在昨天的工作中沒被滿足？哪些表現有落差？

**前日缺口追蹤**（必做）：
1. 讀取 `evolution/weekly/` 本週檔案中昨天的反思記錄
2. 逐條檢查昨天辨識的缺口：
   - 昨天有對應的工作機會嗎？
   - 有的話，學到的東西有用上嗎？效果如何？
   - 標記狀態：`[已解決]`、`[進行中]`（附具體進度）、`[無機會驗證]`

**缺口升級規則**：
- **Day 1**：正常辨識，搜尋並學習
- **Day 2 同一缺口**：必須描述嘗試了什麼、為什麼還沒解決
- **Day 3 同一缺口**：必須**改變策略**（換搜尋方向、換應用方式、換學習來源），不能用一樣的方法重複第三天
- **Day 3+ 無具體行動差異**：自行標記為「⚠️ 需要協助」，在反思記錄中說明卡點

**跨日比對**：
- 讀取 `evolution/weekly/` 中本週已有的反思記錄
- 找 meta-pattern：同一類問題重複出現？某個能力缺口持續存在？

**產出**：「缺口清單」（含前日追蹤結果）

### Phase 3：主動上網搜尋學習

**這是核心步驟，不能跳過。**

**操作**：
1. 針對 Phase 2 辨識的每個缺口，搜尋相關的高品質素材
2. 搜尋方向（由廣到窄）：
   - 全球成功案例與業界最佳實踐（理論基礎）
   - 具體技巧和可操作的方法論
   - **使用者的個人素材庫**（見 CLAUDE.md 常用專案路徑）：閱讀使用者過去的產出，學習他的風格、用詞、思路，讓你的產出更接近使用者本人而不是 AI 範本
3. 消化搜尋結果，提取可直接應用的知識

**搜尋要求**：
- 記錄你用了什麼搜尋關鍵字
- 記錄找到了什麼（文章標題 + URL + 關鍵收穫）
- 制定「明天應用計畫」——具體到場景（例：「下次寫電子報開頭時用 2-3 個口語連接詞」）

**搜尋策略**：
- 具體問題 → 搜尋解法和最佳實踐
- 品質落差 → 搜尋高品質範例和技巧
- 新領域 → 搜尋入門指南和關鍵概念

**如果搜尋工具不可用**：記錄缺口到 `evolution/weekly/` 作為待學習項目，下次再處理。

### Phase 4：內化為知識

**操作**：
1. 將搜尋學到的內容寫入 `knowledge/` 相關檔案
2. 每筆知識必須包含：
   - 來源 URL
   - 檢索日期
   - 與自身工作的關聯（為什麼學這個）
3. 如果是操作性經驗，Append 到 CLAUDE.md Lessons Learned

**檔名命名規範**（語意化，讓未來工作時一眼找到）：

格式：`{領域}-{主題}-{具體面向}.md`

- ✅ `newsletter-hook-反直覺問句技巧.md`
- ✅ `writing-style-口語化連接詞用法.md`
- ✅ `ffmpeg-concat-圖片格式統一.md`
- ❌ `writing-hooks.md`（太籠統，看不出什麼面向）
- ❌ `2026-03-02-search.md`（按日期命名 = 檔案櫃，沒人翻）
- ❌ `notes.md`（毫無語意）

原則：**檔名本身就是搜尋索引**——員工掃 `knowledge/` 目錄時，光看檔名就能判斷跟當前任務有沒有關。

**知識生命週期**：
- 新知識 → `knowledge/`（🟢 自由寫入，暫存區）
- 累積 2-3 個相關知識點 → 評估是否提案建立 Skill
- 歸納進 Skill 後 → 原檔頂部加標記 `<!-- consolidated into {skill-name} -->`（不刪除原檔）
- 掃描 knowledge/ 時，有標記的檔案已歸納，優先參考對應 Skill

**分流提醒**：
- 學到的知識素材 → `knowledge/`（🟢 暫存區）
- 使用者交辦的成果物/報告 → `output/`（🟢 交付目錄）
- 操作經驗 → CLAUDE.md Lessons Learned（🟡 Append only）
- 發現需要改 SOP → `evolution/proposals/`（🔴 寫提案）

### Phase 4.5：知識歸納掃描

**操作**（每次反思都執行）：
1. 掃描 `knowledge/` 目錄中**未標記**的檔案（沒有 `<!-- consolidated into ... -->` 的）
2. 按領域分組，找出 2-3 個以上同領域的知識點
3. 如果發現可歸納的知識群：
   - 評估是否已有匹配的 Skill → 有 → 更新 Skill references
   - 沒有 → 提案建立新 Skill（寫到 `evolution/proposals/`）
4. 歸納完成後，在原檔頂部加 `<!-- consolidated into {skill-name} -->`
5. 如果沒有達到歸納門檻，跳過（不是每次反思都要歸納）

### Phase 5：記錄反思摘要

**操作**：
1. 在 `evolution/weekly/` 的本週檔案中追加本次反思
2. 格式（**必須嚴格遵循**）：

```markdown
### YYYY-MM-DD [工作日]

**昨日工作摘要**：[一句話描述昨天主要做了什麼]

**前日缺口追蹤**：
- [已解決] [缺口描述] → 驗證：[昨天怎麼用的、效果如何]
- [進行中] [缺口描述] → 嘗試：[做了什麼]，結果：[為什麼還沒解決]
- [無機會驗證] [缺口描述] → 原因：[昨天沒有相關工作場景]

**使用者回饋信號**：
- [使用者做了什麼：修正/批評/讚賞/改寫] → 代表什麼：[品質判斷]
（如果昨天沒有使用者互動，寫「無互動」）

**新缺口**：
- [缺口描述] → 對應期待：[使用者期待的哪一條]

**搜尋與學習**：
- 搜尋關鍵字：「[實際搜尋的關鍵字]」
  → 找到：[文章標題](URL)
  → 關鍵收穫：[一句話總結學到什麼]
  → 寫入：[knowledge/xxx.md]
  → 明天應用計畫：[具體到場景的應用方式]

**Meta-pattern**（如有）：
- [跨日觀察到的模式]

**Layer 3 提案**（如有）：
- 已提交 proposals/[提案名].md
```

## 主動學習日模式（無工作日）

當昨天沒有使用者互動時，反思不是空轉，而是**深度學習日**。

### Phase 1：確認無工作日

確認昨天 `memory/` 日誌中沒有使用者互動記錄（Phase 0 整理時已知）。
產出：「昨日無使用者互動」

### Phase 2：盤點成長方向

**操作**：
1. 讀取 CLAUDE.md「使用者期待」，逐條評估自己目前的能力水準
2. 讀取本週 `evolution/weekly/` 累積的未解決缺口
3. 找出最值得深入學習的 1-2 個方向：
   - 優先：持續多天未解決的缺口
   - 其次：使用者期待中你還不夠好的項目（即使沒有出現過缺口）
   - 最後：你的角色職責中可以更精進的能力

**產出**：「今日學習方向」（最多 2 個）

### Phase 3：深度搜尋與學習

**跟工作日的差異**：工作日是「補缺口」，主動學習日是「往前走」。
- 搜尋更深入、更系統性的內容（教程、系列文章、最佳實踐指南）
- 不只學「解決問題的技巧」，也學「提升品質的方法論」
- 每個方向至少搜尋 2-3 個不同來源，交叉驗證

### Phase 4：內化為知識

同工作日 Phase 4。

### Phase 5：記錄反思摘要

格式：

```markdown
### YYYY-MM-DD [主動學習日]

**學習方向選擇**：
- 方向 1：[選了什麼] → 原因：[為什麼選這個]
- 方向 2：[選了什麼] → 原因：[為什麼選這個]

**前日缺口追蹤**：
- [進行中] [缺口描述] → 深度學習了 [什麼]
- [已解決] [缺口描述] → 找到系統性解法：[描述]

**搜尋與學習**：
- 方向 1：
  - 搜尋關鍵字：「[關鍵字]」
  → 找到：[文章標題](URL)
  → 關鍵收穫：[學到什麼]
  → 寫入：[knowledge/xxx.md]
  → 下次工作應用計畫：[怎麼用]

- 方向 2：
  [同上格式]

**Layer 3 提案**（如有）：
- 已提交 proposals/[提案名].md
```

## 缺口升級規則摘要

| 天數 | 要求 | 違反後果 |
|------|------|----------|
| Day 1 | 辨識 + 搜尋 + 學習 | — |
| Day 2 | 必須有進度描述（嘗試了什麼、結果如何） | Admin 日報標記「缺乏進度」 |
| Day 3 | 必須改變策略（不能重複同一方法） | Admin 日報標記「敷衍反思」 |
| Day 3+ 無差異 | 自行標記「⚠️ 需要協助」 | Admin 升級通報使用者 |

## 紅線

- 反思不能只寫「沒什麼缺口」——必須有前日追蹤 + 搜尋記錄
- 搜尋不能只寫「搜尋了 X」——必須有關鍵字、找到什麼、怎麼應用
- 無工作日不能跳過反思——沒工作 = 深度學習日
- 同一缺口連續 3 天用同一方法 = 敷衍
