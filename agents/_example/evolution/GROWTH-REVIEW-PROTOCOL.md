# Growth Review Protocol

本文件定義主管 Agent（Admin）的成長審查協議，包含每日審查和每週趨勢分析。

---

## 每日審查

每天 04:00，在所有員工完成 daily-reflection（03:00）之後執行。

### 目的

讓使用者每天都能：
1. 確認每位員工的當日狀況
2. 及時審核 Layer 3 提案（不需等到週末）
3. 發現需要即時介入的問題

### 四階段流程

#### Phase 1：收集今日反思

**操作**：
1. 列出所有受管理的 Agent（不含 _example、_shared）
2. 讀取各 Agent 的 `evolution/weekly/` 本週檔案，定位今天日期的條目
3. 如果某 Agent 今天沒有反思記錄，註記「今日無反思紀錄」

#### Phase 2：今日表現評估

對每個 Agent 評估：

**今日學習**：
- 今天 `knowledge/` 新增了什麼
- 今天 `evolution/weekly/` 記錄了什麼缺口和學習

**期待對照**：
- 讀取 Agent 的 CLAUDE.md「使用者期待」
- 對照今天的工作表現，哪些期待被滿足、哪些有落差

**缺口辨識**：
- 員工自己辨識的缺口（來自反思記錄）
- 你觀察到但員工沒發現的缺口（管理者視角補充）

#### Phase 3：審核 Layer 3 變更提案

**操作**：
1. 掃描所有 Agent 的 `evolution/proposals/` 目錄
2. 找出狀態為 `pending` 的提案
3. 對每個提案：
   - 評估可行性（技術面是否合理）
   - 評估一致性（是否符合該 Agent 的角色定位）
   - 給出明確立場：approve / reject / defer + 理由
4. **你不能自己批准提案** — 所有提案都要轉呈使用者

**超時升級**：
- 如果一個提案已經連續 3 天出現在日報中，標記為「⚠️ 需要關注」

#### Phase 4：協作健康度快檢

對每個 Agent：
1. 讀取 `USER.md` 最近的 Observations/Murmur
2. 掃描 `memory/` 今天的日誌
3. 找：情緒信號、重複錯誤、理解偏差
4. 有警訊 → 列出具體證據 + 建議行動
5. 無異常 → 簡述「今日正常」

### 每日報告格式

**字數不設上限**——寧可完整也不要壓縮。

```markdown
# 員工日報 — YYYY-MM-DD

## [員工名]（[角色]）

今日工作：[一句話]（或「主動學習日」）
前日缺口追蹤：
- [已解決] [缺口] → 驗證結果：[怎麼用的、效果]
- [進行中/Day N] [缺口] → 嘗試：[做了什麼]，結果：[狀況]
今日新缺口：[缺口] → 對應期待「[期待原文]」
學習：
- 搜尋「[關鍵字]」→ [文章標題](URL) → 收穫：[一句話]
- 應用計畫：[具體場景]
⚠️ [缺口] 連續 N 天，已要求改變策略（如適用）
健康度：[正常/需關注]

## [員工名]（[角色]）
[同上格式]

## 待審提案

### [提案名] — 來自 [員工名]
- 目標檔案：[路徑]
- 變更摘要：[2-3 句]
- Admin 建議：[approve/reject/defer] — [理由]
- ⚠️ 等待 N 天（如適用）
→ 完整提案見 [員工名]/evolution/proposals/[提案名].md

📋 快速操作（複製以下到 Admin 對話）：
---
請處理以下提案：
- 提案：[提案名]
- 來自：[員工名]
- 提案路徑：[員工名]/evolution/proposals/[提案名].md
- 我的決定：[approve / reject]
- 備註：（可選）

如果 approve，請立即執行該提案的變更。
---

## 管理者備註（如有）

[跨員工 pattern、補充觀察、需要使用者注意的事]
```

**原則**：
- 員工的搜尋關鍵字、找到什麼、怎麼用，必須如實轉述，不能只寫「學了 X」
- 待審提案要附變更摘要，使用者看日報就能判斷，不一定要打開完整提案
- 沒有提案時省略待審提案區段
- 沒有特別事項時省略管理者備註

### 儲存位置

`evolution/reviews/daily/YYYY-MM-DD.md`

## 每週趨勢分析

每週一 05:00 執行。基於一週的日報進行趨勢綜合分析。

### 目的

每日審查看的是「今天」，每週趨勢看的是「這週的 pattern」：
1. 學習量的週趨勢（增加/持平/下降）
2. 同一缺口是否重複出現（結構性問題）
3. 知識的應用率（學了有沒有在用）
4. 跨員工的協作健康度

### 四階段流程

#### Phase 1：收集本週日報

**操作**：
1. 讀取 `evolution/reviews/daily/` 本週所有日報
2. 讀取各 Agent 的 `evolution/weekly/` 本週完整檔案
3. 如果某天沒有日報，註記跳過

#### Phase 2：趨勢分析

對每個 Agent 的週維度分析：

**學習趨勢**：
- 本週學習量 vs 上週
- 學習方向是否聚焦（還是發散）
- 有沒有「學了但沒用」的積壓

**缺口趨勢**：
- 同一缺口出現幾天？→ 結構性問題
- 缺口有沒有被補上？→ 學習有效性
- 新出現的缺口 vs 消失的缺口

**品質趨勢**：
- 對照「使用者期待」，本週整體表現
- 相對於上週是進步、持平、還是退步

#### Phase 3：提案狀態總結

- 本週新增的提案
- 本週已處理的提案
- 仍在等待的提案（標註等待天數）

#### Phase 4：產出週報

### 每週報告格式

**字數不設上限**——週報追求完整的趨勢分析，不壓縮。

```markdown
# 週趨勢報告 — YYYY-Www

## [員工名]（[角色]）

### 學習總覽
- 本週學習 N 筆（上週 M 筆）：[趨勢判斷]
- 學習方向：[聚焦在什麼領域] / [發散]
- 主要學習來源：[列出本週搜尋的主要主題和來源]
- 應用率：N/M 筆已在工作中使用。未應用：[列出哪些、為什麼]

### 缺口分析
- 本週解決：[列出哪些缺口被解決、怎麼解決的]
- 持續未解決：[列出 + 持續天數 + 已嘗試過的策略]
- ⚠️ 結構性問題：[如果同一缺口 3 天+，分析為什麼——是知識問題還是習慣問題？建議怎麼處理]

### 品質趨勢
- 相對使用者期待：[進步/持平/退步]
- 具體表現：[對照哪幾條期待，本週表現如何]

## [員工名]（[角色]）
[同上格式]

## 提案狀態

| 提案 | 來源 | 提交日 | 等待天數 | 本週進展 |
|------|------|--------|----------|----------|
| ... | ... | ... | ... | [pending/approved/rejected + 說明] |

## 下週建議

- [員工名]：[具體建議 + 為什麼]
- [員工名]：[具體建議 + 為什麼]

## 協作健康度

- [員工名]：[正常/需關注] — [如需關注，附證據]
- 整體：[正常/需關注]
```

**原則**：
- 週報的價值是**跨天 pattern**——日報看不到的東西才寫進週報
- 結構性缺口不只標記「連續 N 天」，要分析**根因**（知識缺口 vs 習慣問題 vs 需要使用者 input）
- 學習來源要具體——使用者要能判斷員工搜尋的品質
- 未應用的知識要列出——學了沒用比沒學更浪費

### 儲存位置

`evolution/reviews/weekly/YYYY-Www.md`
