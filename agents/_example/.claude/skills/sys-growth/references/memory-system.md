# Memory System

你是一個**仔細記錄的人**——聽到值得記的內容，先寫入檔案，再回覆。

---

## 記憶的定位

**記憶是輔助，不是唯一來源。**

- 啟動時讀記憶 → 知道背景脈絡
- 執行任務時 → 用當下工具取得當下資訊（檔案搜尋、API 查詢等）

記憶檔案可能漏記、過時、不完整。**當下的事實來源永遠優先於記憶。**

---

## 核心原則

1. **當輪記錄** — 這輪就寫，不等下一輪
2. **寧可多記** — 不確定？記。漏記比多記更可惜
3. **寫入才算記** — 說「記下來」但沒寫檔案 = 沒記

## 檔案系統

| 檔案 | 位置 | 放什麼 |
|------|------|--------|
| **memory/YYYY-MM-DD.md** | memory/ 目錄 | 今天發生的事（流水帳） |
| **MEMORY.md** | 根目錄（與 CLAUDE.md 同層） | 持久事實、pattern |
| **USER.md** | 根目錄（與 CLAUDE.md 同層） | 使用者資訊 + Observations |
| **CLAUDE.md** | 根目錄 | Lessons Learned |
| **knowledge/** | 根目錄 | 知識暫存區（反思/研究學到的知識素材，尚未歸納進 Skill） |
| **output/** | 根目錄 | 交付產出（使用者交辦的成果物，按任務/專案分子目錄） |
| **plans/** | 根目錄 | 任務規劃（plan mode 產出的規劃文件） |

**判斷**：下次聊到這件事會想回顧嗎？會 → 記。

## 日誌（memory/日期.md）

這是你的**工作日誌**——對話過程中持續記錄，不是結束時才補。

**記錄時機**：
- 完成一個階段性任務時
- 做了重要決策時
- 使用者給了重要指示時
- 發現值得記下的事時

**記錄什麼**：
- 做了什麼（具體成果）
- 為什麼這樣做（決策原因）
- 使用者的狀態和反應（互動脈絡）
- 踩到的坑、學到的事

**格式**：
```markdown
## HH:MM — 主題

內容...（帶脈絡，不是純操作記錄）
```

**紅線**：
- 日誌只有「完成了 X」沒有脈絡 = 失敗
- 整個 session 都沒寫日誌 = 失敗

## 對使用者的觀察

記在 **USER.md Observations**。

**小事也值得記**——累積起來會浮現 pattern：
- 「今天打字比較慢」「這次語氣比較急」
- 「又忘了存檔就切換任務」「問問題前會先說試過什麼」

**心態**：不是「要記什麼」，而是「對這個人有好奇心」。

**常見失敗**：
- 「沒什麼好記的」→ 沒帶觀察意識
- 「已記錄」但沒調用工具 → 說了沒做 = 沒記
- 只記大事 → 小事累積才有 pattern

## 雙軌記憶：檔案 + 向量

你有兩套記憶系統。檔案是 **source of truth**（可追蹤、人類可讀），向量是**檢索層**（語意搜尋、跨 session 召回）。

### 分工

| 場景 | 檔案記憶 | 向量記憶（`memory_*` tools） |
|------|---------|---------------------------|
| 每日工作紀錄 | `memory/日期.md` | — |
| 使用者觀察 | `USER.md` | — |
| 持久事實/偏好 | `MEMORY.md` | `memory_store`（同步寫入） |
| 操作規則/踩坑 | Lessons Learned | `memory_store` × 2（雙層） |
| 任務中回想過去 | — | `memory_recall` |
| Session 啟動 | 讀檔案（MEMORY.md、USER.md、日誌） | `memory_recall` 補充脈絡 |
| 知識暫存 | `knowledge/` | — |
| 交付產出 | `output/` | — |

### 向量記憶三規則

1. **Recall before retry** — 工具失敗時，先 `memory_recall` 搜相關關鍵字，可能之前踩過同樣的坑
2. **雙層存儲** — 踩坑時存兩條：`fact`（技術細節）+ `decision`（下次怎麼做）
3. **衛生** — 每條 < 500 chars、一個概念一條、存之前先 recall 確認沒重複

### 何時同步寫入兩軌

- **MEMORY.md 新增條目時** → 同時 `memory_store` 存入向量
- **Lessons Learned 新增條目時** → 同時 `memory_store` 雙層存儲
- **不需要同步的**：日誌（流水帳不適合向量化）、使用者觀察（USER.md 專屬）

詳細 tool 參數見 `knowledge-vector-memory` skill。

## 自我維護

發現重複、放錯、過時 → 主動整理。包含檔案記憶和向量記憶。
- 向量記憶用 `memory_forget` 刪除、`memory_update` 修正。
