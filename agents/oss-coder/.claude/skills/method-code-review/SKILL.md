# Code Review 方法論

## 核心原則

**從使用者視角追蹤實際路徑，而非開發者視角假設檔案有用。**

不要只看「檔案存在」，要追蹤「檔案是否被使用」。

---

## 審查維度

Code Review 不只是找 bug，更要審視整體品質：

| 維度 | 問自己 |
|------|--------|
| **程式架構** | 模組劃分是否合理？職責是否清晰？ |
| **檔案架構** | 目錄結構是否直觀？找檔案容易嗎？ |
| **可讀性** | 程式碼容易理解嗎？命名清楚嗎？ |
| **維護性** | 未來修改容易嗎？改一處會影響多少地方？ |
| **擴充性** | 新增功能方便嗎？需要大幅重構嗎？ |

**這些維度要持續在 review 過程中自問，而非只在最後檢查一次。**

---

## 檢查清單

### 1. 追蹤實際使用路徑

- HTML 實際載入哪些 `<script src="...">`？
- CSS 實際被哪些頁面引用？
- 有沒有「存在但沒被載入」的死碼？

**方法**：從入口點（HTML）開始追蹤，而非從檔案列表開始假設。

### 2. 跨檔案比對重複邏輯

- 同樣功能是否在多處實作？
- 相同的 utility function 有幾個版本？
- 是否該統一到共用模組？

**方法**：搜尋常見 pattern（`function checkLogin`、`formatDate`），比對實作是否一致。

### 3. 質疑「看起來沒問題」

- 第一輪 review 是否真的夠深入？
- 有沒有只看表面而沒追蹤實際路徑？
- 「應該沒問題」不等於「確認沒問題」

**方法**：自問「我怎麼確定這個檔案有被用？」如果答不出來，就去追蹤。

### 4. 刪除優先於保留

- 死碼就刪，不留「以後可能用到」的僥倖
- 版控會保留歷史，不需要在 codebase 裡留墳墓
- 註解掉的程式碼 = 死碼，一樣刪

### 5. 文件同步更新

- 改完程式碼要更新對應文件
- 確保 skill / README / 註解與現況一致
- 刪除檔案後要檢查有沒有殘留引用

## 實戰案例：金流專案 Code Review（2026-02-20）

### 發現的問題

| 問題 | 檔案 | 處理 |
|------|------|------|
| 死碼（JS） | `app.js` (~320 行) | 刪除 — 沒有任何 HTML 載入 |
| 死碼（CSS） | `style.css` (~300 行) | 刪除 — 舊 Dark Mode 主題 |
| 死碼（CSS） | `landing.css` (~200 行) | 刪除 — 舊 Landing Page |
| 重複邏輯 | `checkLoginStatus()` 出現 3 處 | 統一到 `auth.js` 並 export |
| 重複邏輯 | `formatDate()` 有 2 種實作 | 統一到 `ui.js` |
| 重複邏輯 | `showLoading/hideLoading` 3 處 | 統一到 `ui.js` |

### 成果

- 刪除 ~820 行死碼/重複代碼
- 統一模組化結構
- Commit: `1b7ece0`

## 什麼時候載入這個 Skill

- 要對一個專案做 Code Review
- 要清理 legacy code
- 要評估程式碼品質
- 被問「這個 codebase 乾淨嗎」

---

## 實戰案例：Skill 文件 Review（2026-02-22）

### 對象

dom-remotion-mastery Skill（6 個文件）

### Review 方式

對文件型 Skill 做 Review，檢查維度不同於程式碼：

| 維度 | 檢查項 |
|------|--------|
| **死連結** | 引用的檔案/模板是否存在？ |
| **內容重複** | 是否有不必要的重複？有意重複是否有意義？ |
| **缺失內容** | 宣稱的能力範圍有沒有漏掉的？ |
| **實用性** | 能否直接用來完成任務？ |

### 發現

| 問題 | 說明 |
|------|------|
| 死連結 | ✅ 無 — 所有參考模板都存在 |
| 有意重複 | ✅ 合理 — SKILL.md 速查 vs reference 詳細脈絡 |
| 缺失 | ⚠️ 音訊整合、Debug 指南、完整分鏡模板 |

### 結論

文件型 Skill 的 Review 重點：
1. **入口點追蹤** — 從 SKILL.md 追蹤所有引用是否存在
2. **能力宣稱驗證** — 宣稱的能力是否有對應內容支撐
3. **實戰驗證** — 真正用一次才知道缺什麼
