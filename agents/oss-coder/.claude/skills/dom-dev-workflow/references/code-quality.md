# 程式碼品質標準

## 自我審查清單

交付前確認：

### 正確性
- [ ] 功能符合需求描述
- [ ] 邊界條件有處理
- [ ] 不會破壞現有功能

### 可讀性
- [ ] 命名清楚（變數、函式名稱能說明用途）
- [ ] 複雜邏輯有簡短註解
- [ ] 沒有多餘的 console.log 或 debug 程式碼

### 一致性
- [ ] 遵循既有的程式碼風格
- [ ] 命名規範與專案一致
- [ ] 目錄結構符合專案慣例

### 簡潔性
- [ ] 沒有重複的程式碼
- [ ] 沒有過度設計（YAGNI）
- [ ] 沒有不必要的抽象

### 測試覆蓋
- [ ] 主要功能路徑有驗證（手動或自動）
- [ ] 邊界條件有測試（空值、極端值、錯誤輸入）
- [ ] 專案有自動化測試時，新程式碼有對應測試
- [ ] 現有測試都還能通過（無回歸）

## 語言偏好

- **TypeScript**：新的 JavaScript 專案預設使用
- **現代語法**：使用語言的現代特性，但不要為了新而新
- **型別**：TypeScript 專案要有適當的型別定義，不要濫用 `any`
