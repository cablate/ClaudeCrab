# 建立領域知識庫

> 來源：2026-02-20 金流 Skill 重構
> 工作類型：為某個專業領域（金流、物流、發票、認證...）建立知識庫 Skill

---

## 這類工作的定位

當專案需要處理某個專業領域時，建立一份該領域的知識庫，讓 AI 能夠：
- 理解領域概念後自己做正確的實作
- 避免踩過的坑
- 面對新需求時知道怎麼思考

**不是**給 AI 一堆程式碼讓它照抄。

---

## 核心原則

### 1. 知識庫，不是實作範本

**精神**：教 AI「學會釣魚」，不是「給一條魚」。

讀完這份知識庫，AI 應該能夠：
- 理解領域概念，自己寫出正確的實作
- 知道關鍵陷阱，自己設計適合專案的方案
- 面對新情境時，知道要注意什麼

AI 不應該：
- 複製貼上某個 SDK 範本
- 被規定 class 要叫什麼名字、用什麼 design pattern

**為什麼**：不同專案有不同的架構、風格、需求。AI 應該根據理解到的概念，做出適合當下 context 的實作。

---

### 2. 內容取捨原則

| 應該包含 | 範例 |
|----------|------|
| **概念** | CheckMacValue 是什麼、為什麼需要 |
| **流程** | 付款 → Webhook → 發票 → 通知 |
| **陷阱** | %20→+ 這個轉換很容易漏 |
| **決策脈絡** | 為什麼選 Print=0、為什麼用綠界載具 |
| **官方 API 規格** | 欄位定義、狀態碼、測試環境資訊 |

| 不應該包含 | 原因 |
|------------|------|
| **完整的 class/function 實作** | 限制 AI 的實作空間 |
| **具體命名建議** | 應由 AI 根據專案風格決定 |
| **設計模式規定** | 應由 AI 根據需求選擇 |
| **從程式碼複製的片段** | 會變成「照抄範本」而非「理解後實作」 |

**判斷方法**：「這段內容是在教概念，還是在規定寫法？」
- 教概念 → 保留
- 規定寫法 → 移除或改為概念說明

---

### 3. 錨定機制

入口文件（SKILL.md）必須包含：

| 項目 | 說明 |
|------|------|
| **給誰用** | 這份知識庫的目標讀者 |
| **用來做什麼** | 讀完能達成什麼 |
| **設計精神** | 為什麼這樣設計（學會釣魚 vs 給一條魚） |
| **不應該包含什麼** | 邊界，防止未來維護者加錯東西 |

**為什麼需要錨定**：沒有錨定，未來維護者（包括未來的我）可能會偏離原意，又開始塞程式碼進去。

---

### 4. 官方文件 vs 自己的程式碼

| 類型 | 處理方式 |
|------|----------|
| 官方 API 文件、規格 | 保留（這是領域知識） |
| 從自己程式碼複製的片段 | 移除（這是實作細節） |
| 踩坑經驗 | 保留概念和解法，移除具體 code |

---

## 建立流程

1. **確定領域範圍**：這份知識庫涵蓋什麼（金流？金流+發票？）
2. **收集官方文件**：API 規格、狀態碼、測試環境
3. **整理核心概念**：這個領域的關鍵概念是什麼
4. **記錄踩坑經驗**：實際開發中遇到的陷阱
5. **寫入口錨定**：SKILL.md 說明定位、精神、邊界
6. **Review 內容**：檢查是否有「規定寫法」的內容，改為「教概念」

---

## 放置位置：可攜性判斷

設計知識庫時，需判斷「這份知識的可攜性」來決定該放哪裡：

| 類型 | 特徵 | 放置位置 | 範例 |
|------|------|----------|------|
| **領域知識** | 跨專案通用、可攜帶 | 通用 agent 的 `.claude/skills/` | 金流串接、發票整合 |
| **專案知識** | 只對特定專案有意義 | 專案內的 `proj-*` Skill | ClaudeCab 架構、模組關係 |

**一句話區分**：
- 領域知識 Skill = 「領域專家」（金流怎麼串）
- 專案知識 Skill = 「專案導遊」（這個專案怎麼運作）

**判斷方法**：「換一個專案，這份知識還有用嗎？」
- 有用 → 領域知識，放通用位置
- 沒用 → 專案知識，放專案內

## 常見陷阱

| 陷阱 | 症狀 | 修正 |
|------|------|------|
| 塞滿程式碼 | 文件裡有完整的 class 實作 | 移除，改為概念說明 |
| 缺少錨定 | SKILL.md 沒說這份文件的定位 | 補上「給誰用、做什麼、設計精神」 |
| 混入專案特定細節 | 寫死了 class 名稱、檔案路徑 | 移除，讓 AI 自己決定 |
| 忘記官方文件 | 只有踩坑經驗，沒有 API 規格 | 補上官方文件（這是領域知識的基礎） |
| 放錯位置 | 領域知識放在專案內、專案知識放在通用位置 | 根據可攜性判斷正確位置 |
