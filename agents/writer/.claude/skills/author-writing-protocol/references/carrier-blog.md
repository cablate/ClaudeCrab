# 部落格載體規範（CabLate）

> 適用：CabLate 部落格文章
> 這份規範涵蓋「怎麼寫」和「怎麼上架」——兩段都在這裡，不需要跳去其他 playbook。

---

## 載體定位

部落格是**深度分析的載體**——有完整論證、有具體案例、有明確立場。

不是社群貼文的加長版，也不是電子報的延伸。部落格文章是獨立成立的，讀者可以不認識 Cab 也能讀懂並有收穫。

---

## 從現成素材轉換（適用：Threads 串文、草稿、筆記等）

使用者提供現成素材要求轉成部落格時，這一節優先讀。

### 核心心態：轉換，不是改寫

現成素材不是「原料」，是「有結構的初稿」。它有兩層東西：
- **可以改善的**：短句堆疊、口語過度、段落缺橋接——這些讓它讀起來像社群貼文
- **必須保留的**：段落的先後順序、因果邏輯線、敘事節奏

常見錯誤：為了讓文章「更有結構」而重排段落。素材的段落順序通常是作者刻意排的，打亂就是打亂因果。

### 動筆前：先畫邏輯線

把每個段落/貼文用一句話概括「這步做了什麼」：

```
段落 1：發現問題 + 觀察到現象
段落 2：初步假設 + 決定深挖
段落 3：深挖結果（機制）
段落 4：找到根因 + 特殊情況
段落 5：解法
```

這條線就是文章的骨架，H2 的順序必須跟這條線對齊。

### 改善什麼、不動什麼

**✅ 可以改善**

| 問題 | 如何處理 |
|------|---------|
| 短句堆疊讀起來像社群貼文 | 合併成段落，加上銜接句 |
| 口語過度 | 視語氣保留或適度收斂 |
| 技術詞彙說明不足 | 加一句解釋 |
| 段落之間缺橋接 | 加銜接句讓前後段有因果感 |
| 過度解讀（比素材說的更強） | 收回到原始素材的陳述 |

**❌ 不能動**

| 項目 | 說明 |
|------|------|
| 段落先後順序 | 這是作者的因果線，不能為了「結構化」而調換 |
| 核心觀點 | 不加、不刪、不升級（「可能有問題」不能變成「設計來欺騙你」） |
| 調查的時序感 | 原文是「觀察→假設→驗證」，不要重排成「結論→解釋」 |

### 常見踩坑

**把「觀察」移到「說明機制」之後**

- ❌ 先解釋機制 → 後面才說「我有觀察到這個現象」
- ✅ 先說「我觀察到這個現象（所以去深挖）」→ 然後說機制

一旦因果顛倒，後面再怎麼通順讀起來都會有違和感。

**在懸念句之後插補充說明**

- ❌「嗅到問題了。另外值得注意的是...」
- ✅ 懸念句後直接進下一 H2，補充說明放到合適的節

**內部連結硬塞進論述句**

- ❌「這跟[某個概念](/articles/xxx)有關——」（把連結嵌進因果句）
- ✅ 在自然出現的地方加，例如補充說明的結尾，或段落開場

### 動筆前確認表

```
□ 已畫出素材的邏輯線（每段一句話）
□ H2 順序和邏輯線對齊
□ 沒有把「後來才知道的事」提前放（時序感保留）
□ 需要橋接的地方（「因為這個觀察，才去做那件事」）已補上銜接句
□ 所有改善都是改語言，沒有改觀點或改順序
□ SEO checklist 過完
```

## 文章結構

### 開場（前 100-150 字）

- 必須點出核心問題或矛盾——不是「今天要介紹...」而是「這件事的矛盾在哪裡」
- 從具體事件或現象切入，不從抽象定義切入
- 讓讀者知道「讀完這篇你會得到什麼判斷工具」，不是「讀完這篇你會學到很多」

### 主體（H2 結構，3-6 個）

- 每個 H2 是論點推進，不是並列的小主題
- H2 標題要含關鍵字變體，不要只寫概念名稱（「AI 理論覆蓋率是什麼？」比「先釐清概念」好）
- 段落 3-5 句，不超過 150 字
- 論點之間是邏輯推進，不是並列堆砌

### 結尾

- 不是「總結」——不要重複前面說過的
- 是「最後一擊」——一句話讓讀者帶著某個觀點或行動方向離開
- 可以邀請讀者留言或互動，但要自然

---

## 語調原則

電子報的「朋友聊天感」在部落格可以收一點——部落格更接近「Cab 在認真講他的觀點」，但仍然：
- 有第一人稱（「我看到的是...」「我認為...」）
- 不裝客觀中立
- 不過度正式（不是學術論文）

---

## 內部連結（SEO + 讀者價值）

在論點自然出現的地方插入 2-3 個內部連結：
- 錨點文字要含關鍵字，不要用「點這裡」「了解更多」
- 優先連同 category 的文章
- 目前可連文章：
  - `/articles/claude-code-workflow`：Claude Code 建站實戰
  - `/articles/blog-writing-openclaw`：自動化與 Agent 的差異

---

## 格式規範

- 草稿若用 `---` 分隔段落，轉成部落格 `.md` 時要改為 `##` 標題（SEO 需要）
- H1 由 frontmatter title 提供，文章內不再加 H1
- 文章總長 ≥ 1500 字
- 圖片插入位置：緊接在第一次提到該圖的段落之後

## CabLate 上架流程

> 專案路徑：`F:/_Program/OwnProject/CabLate`
> 技術棧：Astro + Cloudflare Pages

### Step 1：建立文章檔案

路徑：`src/content/articles/{slug}.md`

slug 規則：語意化英文、全小寫、`-` 分隔（如 `anthropic-radar-ai-cannot-replace`）

### Step 2：填寫 Frontmatter

```yaml
---
title: ""           # 50-60 字元，含主要關鍵字（不要加 | CabLate，由 Astro SEO 組件自動處理）
description: ""     # 120-155 字元，回答「為什麼要讀這篇」，含關鍵字
publishDate: YYYY-MM-DD
category: ""        # 只能四選一：技術觀點 / AI工具實戰 / 自動化流程 / 創業思考
tags: []            # 3-5 個：1 主要關鍵字 + 2-3 相關技術詞 + 1 通用詞
featured: false
readingTime: N      # 分鐘數（每分鐘約 250-300 字）
draft: false
excerpt: ""         # 80-120 字元，口語化，像朋友推薦
ogImage: ""         # 有 OG 圖才填："/images/articles/{slug}/og.webp"
faq:                # 必填！3-5 組 Q&A，聚焦文章核心關鍵字
  - question: ""
    answer: ""
---
```

**Red lines（不能犯）：**
- `category` 只能四個合法值，不能自創（如 `ai-analysis`）
- `faq` 不能省略——結構化資料對 SEO 很重要
- `excerpt` 80-120 字元，不是越長越好

### Step 3：處理圖片（如有）

```bash
# 建目錄（slug = 文章檔名）
mkdir -p "public/images/articles/{slug}/"

# 內文圖（品質 80，最大寬 1440px）
ffmpeg -i input.jpg -c:v libwebp -quality 80 -vf "scale=1440:-1:flags=lanczos" {slug}/{name}.webp -y

# OG 圖（品質 85，固定 1200x630）
ffmpeg -i input.jpg -c:v libwebp -quality 85 -vf "scale=1200:630:force_original_aspect_ratio=decrease,pad=1200:630:(ow-iw)/2:(oh-ih)/2" {slug}/og.webp -y
```

**圖片 alt text：**
- 描述圖片在文章脈絡中的意義，不是單純描述畫面
- 首字大寫，**結尾加句號**（必要！）
- 好的範例：`Anthropic 發布的職業類別 AI 理論覆蓋率（藍色）與實際使用率（紅色）對比雷達圖，顯示兩者之間的巨大落差。`

### Step 4：Build 驗證

```bash
cd "F:/_Program/OwnProject/CabLate"
npm run build
```

確認 build 成功、無 error 再 push。

### Step 5：Git Push 上線

```bash
git add src/content/articles/{slug}.md public/images/articles/{slug}/
git commit -m "feat: 新增文章「{標題}」"
git push
```

`git push` 後 Cloudflare Pages 自動部署，不需手動 wrangler deploy。

## 常見踩坑

| 問題 | 解法 |
|------|------|
| `category` 用了自創值 | 只用四個合法值 |
| 沒有 `faq` 欄位 | 每篇文章都要有，SEO 結構化資料 |
| H2 沒有關鍵字 | 把主題詞帶進 H2 標題 |
| alt text 沒有句號 | 結尾加句號是規定 |
| excerpt 太短或太長 | 80-120 字元，大約 2-3 句 |
| 用 `---` 分隔段落而不是 `##` | 轉成部落格格式時改為 H2 |
| 素材段落順序被調換 | 先畫邏輯線，H2 順序跟邏輯線對齊 |
| 內部連結嵌進論述句 | 放在補充說明或段落開場，不要插進因果句 |
