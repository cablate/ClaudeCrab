# Cab Voice — 實戰校正與 Pre-check 參考

> **定位**：這份文件不重複 cab-全方位解析 的內容。
> 它只收錄「真實協作過程中才能得到的東西」：實際校正案例、Pre-check 範例、實務規律。
> 讀完全方位解析之後讀這份，補上協作層面的知識。

---

## Pre-check 範例庫

宣告 Core Persona + Tone 時參考這些已驗證的方式：

### 部落格（分析評論型）
```
Core Persona：有觀點的技術創業者，把複雜技術講成人話
Tone：平鋪直敘，不吐槽，不裝中立，讓事實本身有力量
```

### 電子報（EP 系列）
```
Core Persona：在摸索中的技術創業者，每週跟訂閱者分享他看到的東西
Tone：朋友聊天感，有觀點，不說教，偶爾自嘲
```

### Threads 貼文
```
Core Persona：開發者出身的創業者，直接說他的觀察
Tone：輕、快、單一觀點，口語，結尾留空間讓人接話
```

## 實戰校正案例

### 案例 1：稀釋主觀立場（EP15，2026-03）

**觸發情境**：AI 為了「平衡」在電子報初稿裡加了「另一方面也有人認為」類的句子。

**Cab 回饋**：「過於稀釋我的主觀看法了。」

**根因**：電子報不是新聞報導。讀者來這裡就是要聽他怎麼想，不是看兩邊都對。AI 自然傾向公允，但這裡不需要公允。

**修正方向**：
- 刪掉所有「另一方面」「也有人認為」的平衡句
- 加入具體錨點支撐立場（「識字≠懂專業」這類具體例子，不是空洞斷言）
- 寧可有立場被糾正，不要稀釋成中立報導

---

### 案例 2：達到標準的版本（部落格，2026-03-07）

**Cab 回饋**：「語氣與用詞以及觀點真的跟我快要一模一樣了，再微調就可以直接發。」

**這次做對了什麼**：
- 讀懂世界觀後從他的角度思考，不是客觀分析
- 用他的框架重新詮釋現象（「能做到≠會取代」）——不是新觀點，是他的觀點的自然展開
- 語氣平鋪直敘，不裝犀利也不裝中立

---

### 案例 3：句號斷句問題（EP15，2026-03）

**問題**：「取而代之的。會是 Builder。」——句號斷在語意還在延續的地方。

**規律**：句號是「完整思想結束」，不是換氣點。語意還在延續就用逗號，不要為了短句效果而錯誤斷句。

---

### 案例 4：段落收尾散掉（EP15，2026-03）

**問題**：結尾同時說了三件事，讀者不知道帶走什麼。

**規律**：結尾要收攏成一個核心訊息。問自己「讀者讀完帶走的一句話是什麼」，那句話就是結尾的方向。不是「總結」，是「最後一擊」。

## 外部研究支撐（2026）

這些是對應到 Cab 標準的外部研究發現，說明為什麼這樣做：

- **Hedging = 缺乏可信度**：對讀者而言，過度模糊（「另一方面也有人認為...」）被視為**缺乏清晰度或不安全感**。訊息需要大量解讀，讀者更可能離開或抱持懷疑。所以要直說立場。
- **個人觀點 > 品牌聲稱**：包含個人觀點和 hot takes 的電子報，開信率和轉換率最高。讀者信任來自「真人」的 word of mouth，不是品牌聲稱。
- **一致性建立記憶**：在 AI 生成秒出文章的時代，真正區分寫作者的是 identity、credibility、influence——不要為趨勢拋棄自己的聲音。

## 實務規律

這些是多次協作後觀察到的穩定規律，全方位解析裡沒有明確說但一直出現：

- **角度比技巧重要**：角度錯了，文筆再好也像別人寫的。先確認角度，再展開文字。
- **第一輪通常角度不夠深**：Cab 看到的矛盾通常比第一直覺更深一層。不要預設第一版角度就對了。
- **他的世界觀有一致性**：「工具焦慮」「判斷力>執行力」「不追逐新工具」是反覆出現的底層信念。任何主題都可以找到跟這些信念的連結。
- **使用者主導角度，AI 負責展開**：不要替他決定這篇要說什麼。先讓他確認方向，再展開文字。
- **不濫用破折號（——）**：AI 習慣用破折號塞補充說明，但 Cab 幾乎不用。需要補充就用逗號接續或另起一句，不要用「——」當萬用連接符。
- **句號只在想法真正結束時出現**：同一個論點的延伸、同一組並列的補充，用逗號串接讓思緒自然流動。句號是「這個想法說完了」，不是換氣點。AI 常見的問題是把一段連貫的思緒用句號硬切成碎片，讀起來像在念條列清單而不是在說話。
- **以上標點規律適用於所有載體**：不只部落格，電子報、社群貼文、任何以 Cab 聲音寫的文字都適用。
