### 核心學習收穫

#### 1. 系統性除錯流程（Personal Debugging Process）

**六步驟**：
1. Take Detailed Notes — 記錄詳細筆記
2. Make Bugs Repeatable — 讓 bug 可重現
3. Isolate Suspicious Modules — 隔離可疑模組
4. Change Only One Thing at a Time — 一次只改一個變數
5. Divide and Conquer — 分而治之
6. Seek Peer Assistance — 尋求同儕協助

來源: [10 debugging techniques](https://wearebrain.com/blog/10-effective-debugging-techniques-for-developers/)

#### 2. Root Cause Analysis (RCA)

**成本驚人的事實**：
- 設計階段發現缺陷：基準成本
- 實作階段發現：2x 成本
- **測試階段發現：15x 成本**

**核心技法**：
- **Five Whys** — 反覆問「為什麼」直到找到根本原因
- **Fishbone Diagram** — 視覺化呈現潛在根因分類

**最佳實踐**：
- Document Thoroughly（徹底記錄）
- Collaborate（多元視角）
- Timing（越快越好）
- Blame-Free Culture（無責備文化）
- Validate Fixes（驗證修復針對根因而非症狀）

來源: [Root Cause Analysis for Software Bugs](https://www.selementrix.ch/blog/how-do-we-perform-effective-root-cause-analysis-instead-of-just-patching)

#### 3. 對照 Cab 的期待

Cab 明確要求的診斷標準（從 USER.md 觀察提取）：
1. **追根究底** — 不接受敷衍解法
2. **先驗證假設** — 有證據支持（log、F12、檔案）
3. **完整維度追蹤** — 不只看單一指標
4. **穩健性優先** — 不喜歡脆弱的判斷方式

**這完全對應到 RCA 的最佳實踐！**

### Phase 3: 主動學習 — 跨平台路徑處理與安全

#### 搜尋關鍵字與來源

1. **"cross-platform path handling Node.js Windows Unix best practices 2026"**
   - 關鍵收穫：應使用 `path.resolve()` 而非字串拼接，使用 `path.sep` 而非硬編碼分隔符
   - 來源：[cross-platform-node-guide](https://github.com/ehmicky/cross-platform-node-guide/blob/main/docs/3_filesystem/file_paths.md)

2. **"Unix path Windows path conversion Node.js path.resolve normalization"**
   - 關鍵收穫：`path.normalize()` 只會依據當前平台正規化，**不會在 Unix/Windows 格式間轉換**
   - 來源：[Node.js Path Documentation](https://nodejs.org/api/path.html)

3. **"permission hook path validation security best practices Node.js 2026"**
   - 關鍵收穫：2026 年 1 月發現關鍵漏洞（CVE-2026-21636）— symlink 可繞過權限檢查
   - 來源：[Node.js Security Best Practices](https://nodejs.org/en/learn/getting-started/security-best-practices), [Node.js Path Traversal Security](https://nodejsdesignpatterns.com/blog/nodejs-path-traversal-security/)

#### 核心學習收穫

**1. 跨平台路徑處理的三個層次**：
- 格式轉換（Unix-style ↔ Windows）
- 路徑正規化（`path.normalize()`）
- 實際路徑解析（處理 symlink）

**2. 權限 Hook 的安全檢查清單**：
1. Path traversal 檢測（`../`, `..\\`）
2. Symlink 實際路徑解析（`fs.realpathSync()`）
3. 正規化後再次驗證白名單
4. 記錄被拒絕的路徑（安全審計）

**3. 反思 3/5 的修復**：
- ✅ 解決了格式轉換問題
- ⚠️ 缺少 path traversal 檢查
- ⚠️ 缺少 symlink 處理
- ⚠️ 缺少二次白名單驗證
