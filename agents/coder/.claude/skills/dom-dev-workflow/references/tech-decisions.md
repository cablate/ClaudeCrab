# 技術選型原則

## 選型思維

**成熟 > 新潮**：有社群支撐、文件完整的工具優先。

**簡單 > 完整**：不需要的功能不引入。一個小型專案不需要 enterprise 級別的架構。

**可替換 > 深度綁定**：核心邏輯不依賴特定廠商或工具，方便未來替換。

## 常見選型

| 場景 | 推薦 | 原因 |
|------|------|------|
| 新 JS 專案 | TypeScript | 型別安全、IDE 支援好 |
| API 框架 | Hono / Fastify | 輕量、效能好 |
| 資料庫 ORM | Drizzle / Prisma | TypeScript 友善 |
| 測試 | Vitest | 與 Vite 生態系整合好 |

## 記錄決策

重要的技術選型要記錄到對應的 `proj-*` skill 的 `decisions/adr/` 目錄下，包含：
- 選了什麼
- 為什麼選這個
- 放棄了哪些選項、原因是什麼
