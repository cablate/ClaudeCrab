# 數字人實作指南

## 快速開始路線圖

### 方案一：最快上手（使用 Fay）

```bash
# 1. 克隆 Fay
git clone https://github.com/xszyou/Fay.git
cd Fay

# 2. 建立虛擬環境
conda create -n fay python=3.10
conda activate fay

# 3. 安裝依賴
pip install -r requirements.txt

# 4. 配置模型（在 config 目錄）
# - 設定 LLM API（OpenAI/DeepSeek）
# - 設定 TTS
# - 設定數字人形象

# 5. 啟動
python main.py
```

**優勢**：
- 僅需 CPU 即可運行
- 一站式整合
- 支援多平台輸出

---

### 方案二：高品質唇形（MuseTalk + TTS）

```bash
# 1. 克隆 MuseTalk
git clone https://github.com/TMElyralab/MuseTalk.git
cd MuseTalk

# 2. 安裝依賴
pip install -r requirements.txt

# 3. 下載預訓練模型
# 參考 README 的模型下載指引

# 4. 準備素材
# - 一張正面照片（或短視頻）
# - 音頻檔案

# 5. 推理
python inference.py --image your_face.jpg --audio your_audio.wav
```

**硬體需求**：
- GPU：4GB+ VRAM（RTX 3050 Ti 可運行）
- 效果：30fps+ 即時（V100）

### 方案三：完整對話系統（Linly-Talker）

### 推流配置

#### RTMP 推流（傳統方式）
```bash
# 使用 FFmpeg 推流
ffmpeg -re -i output.mp4 \
  -c:v libx264 -preset veryfast \
  -c:a aac -f flv \
  "rtmp://live-push.xxx.com/live/streamkey"
```

**特點**：
- 延遲：3-5 秒
- 穩定性高
- 適合單向直播

#### WebRTC 推流（低延遲）
```javascript
// 前端 WebRTC 推流範例
const pc = new RTCPeerConnection(config);
const stream = await navigator.mediaDevices.getUserMedia({
  video: true,
  audio: true
});
stream.getTracks().forEach(track => pc.addTrack(track, stream));
```

**特點**：
- 延遲：< 500ms
- 適合即時互動
- 需要 WebRTC 伺服器

#### OBS 虛擬攝像頭
```bash
# 將數字人輸出到虛擬攝像頭
# OBS → 虛擬攝像頭 → 直播平台
```

**適用**：
- 快速測試
- 與現有直播流程整合

## 常見問題排查

### 唇形不同步
- **原因**：TTS 輸出與 THG 輸入不匹配
- **解決**：確保音頻採樣率一致（通常 16kHz 或 22050Hz）

### 延遲過高
- **原因**：模型推理慢或網路延遲
- **解決**：
  - 使用 TensorRT 加速
  - 啟用流式處理
  - 部署在靠近用戶的區域

### 數字人表情僵硬
- **原因**：使用 2D 方案限制
- **解決**：升級到 SadTalker 或 3D 方案

### 平台封號風險
- **原因**：違反平台數字人政策
- **解決**：
  - 抖音要求真人驅動
  - 添加必要的互動功能
  - 遵守平台規範
